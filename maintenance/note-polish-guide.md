# 서브노트 문장 다듬기 기준 (content/01_IT Tech)

정보관리기술사 답안용 서브노트를 Gemini 초안에서 정리본으로 다듬을 때 따르는 기준. 이미 정리된 노트(아래 "정리 완료 예시")와 같은 수준을 목표로 한다.

## 1. 구조 (유지)

- frontmatter: `title`, `date`, `tags` 유지. 다른 이름으로 많이 불리는 토픽은 `aliases` 추가.
- `# 제목` → `---` → `## I. ~, ~의 개요` → `## II. 구조·구성요소` → `## III. 비교 및 동향` → `---` → `### 🔗 연관 토픽` 블록.
- I장: `### 가. 정의` (한 문장, 핵심어 굵게) + `### 나. 특징/필요성` (2열 표 `구분 | 내용`).
- II장: `### 가.` 개념도(mermaid 또는 기존 SVG 유지) + 1~2줄 설명, `### 나.` 3열 표 `구분 | 요소 | 설명`. 같은 구분이 연속되면 두 번째 행부터 첫 칸을 비운다.
- III장: 비교표 1개 이상 + `### 나. 동향` 불릿 2~3개.
- 연관 토픽 블록(소속 도메인 / 세부 분류 / 핵심 연관 토픽 5개)은 형식 유지. 자기 자신·중복 링크 제거.

## 2. 문장

- 개조식 명사형 종결("~함", "~임" 남발 대신 "~ 보장", "~ 제공" 또는 짧은 서술). "~하는 핵심 기술임" 같은 상투어 제거.
- 제목 수식어 줄이기: "I. 초고신뢰성 및 유선급 연결성 보장을 위한 차세대 무선랜 표준, X의 개요" → "I. 속도에서 신뢰성으로, X의 개요".
- "요소기술(키워드)", "세부 설명 및 특징" 같은 장황한 표 헤더 → "요소", "설명".
- 과장 제거: "100% 보장", "완벽히", "압도적", "패러다임이 빠르게 전환" 등.
- 같은 내용이 개요·표·동향에 반복되면 한 곳에만 남김.
- 채팅 흔적(“끝”, "~답안입니다", "지시하신", cite 표기) 삭제.

## 3. 사실 검증 (가장 중요)

- 정의·수치·연도·표준 번호를 확인하고 틀리면 고친다. 확신이 없으면 수치를 빼거나 "예:"로 표시.
- 이전 정리에서 실제로 고친 오류 유형: 정족수 조건(W+R>N), Bakery 알고리즘은 상호배제, O/Ω/Θ 정의, ISMS-P 101개 항목, MLE·MAP와 L1/L2 대응, 매니페스토 좌우 가치 방향, 코사인 유사도는 거리 공리 불만족 등.
- 동향은 실제 존재하는 기술·표준·제품만 (가짜 버전명·가짜 일정 금지).

## 4. 링크

- 위키링크 대상이 의미에 맞는지 확인. 동음이의어 주의:
  - `[[MAC]]` = 강제적 접근통제/메시지 인증코드만. MAC 주소는 링크 없이, 곱셈누산은 `[[MAC 배열|MAC]]`.
  - `[[캡슐화]]` = 객체지향 캡슐화만. 패킷·키 캡슐화는 링크 없이.
  - `[[CSP]]` = Cloud Service Provider만.
- 표 안의 별칭 링크는 `[[대상\|별칭]]` (파이프 이스케이프).
- 없는 노트로 링크하지 않는다. 존재 여부는 파일명과 frontmatter aliases로 확인.
- 파일 삭제·이름 변경은 하지 않는다 (링크·MOC·인쇄 쪽번호에 영향).

## 5. 다이어그램

- mermaid: 노드 라벨에 `|`, 따옴표 없는 괄호·특수문자 주의 (`["..."]`로 감싸기). 엣지 라벨에 `|` 금지.
- 기존 inline `<svg>`는 내용이 맞으면 그대로 둔다(수정 시 통째로 보존).

## 6. 정리 완료 예시

2PL, 병행 제어, 네트워크 계층, 데이터 링크 계층, 전송 계층, TCP 혼잡제어, 해시 테이블, 거리 공식, 확률분포, 추정 이론, UML, 유즈케이스 다이어그램, 난독화, 애자일 선언문, Wi-Fi 8, 빅데이터 감리, 공통감리 절차, SW사업 대가산정 가이드, 클라우드 컴퓨팅의 배치 모델 유형, DB 회복기법, 캐시 일관성, 시스템 카탈로그, 카오스 엔지니어링.

## 7. 작업 방식

- 한 번에 노트 4~6개씩 읽고 다시 쓴다. SVG가 있는 노트는 SVG 블록을 그대로 보존.
- 각 도메인 MOC(`00_<도메인>_MOC.md`)의 목록 순서대로 진행, 끝나면 정리한 노트 목록과 고친 사실 오류를 보고.
- 커밋은 하지 않는다.
