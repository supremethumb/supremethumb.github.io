# 공통감리 절차 (정보시스템 감리 절차)

---

## I. 정보화 사업의 품질 확보와 위험 통제, 공통감리 절차의 개요

### 가. 정의

- 독립된 제3자(감리법인)가 정보시스템 구축 사업의 효율성과 안전성을 확보하기 위해 **예비조사 → 감리계획 수립 → 현장감리 → 감리보고 → 시정조치 확인**으로 수행하는 표준 절차 (「정보시스템 감리기준」, 행정안전부 고시)

### 나. 필요성 및 특징

| 구분 | 내용 |
| --- | --- |
| 법적 근거 | 「전자정부법」 및 「정보시스템 감리기준」에 따른 의무 감리 |
| 객관적 검증 | 감리 점검 프레임워크(절차·산출물·성과품 관점) 기반의 체계적 점검 |
| 위험 예방 | 요구정의·설계·종료 등 단계별로 결함을 조기에 식별하고 개선 권고 |
| 이해관계 조율 | 발주기관과 사업자 간 요구사항·구현 결과에 대한 이견 조정 |

- 예비조사로 점검 기준을 정하고, 현장감리에서 결함을 도출해 개선을 권고한 뒤, 사업자의 조치 결과를 감리원이 다시 확인하는 순환 구조

### 나. 단계별 핵심 활동

| 단계 | 활동 | 설명 |
| --- | --- | --- |
| 예비조사 | 사업 현황 파악 | 제안요청서(RFP), 사업수행계획서, 과업내용서 검토로 범위와 중점 점검 항목 도출 |
| | 감리계획서 수립·통보 | 감리 일정, 점검 영역·체크리스트, 투입 감리원 확정 후 발주기관·사업자에 통보 |
| 현장감리 | 착수회의 | 발주기관·사업자·감리원이 감리 방향과 협조 사항 공유 |
| | 감리 수행 | 산출물 검토, 담당자 면담, 시스템 테스트·코드 점검으로 결함 도출 |
| | 보고서 작성·교차 검토 | 지적 사항과 개선 권고안 작성, 감리원 간 검토로 객관성 확보 |
| | 종료회의 | 지적 사항 설명, 사업자·발주기관의 소명 청취와 이견 조율 |
| 보고 | 감리수행결과보고서 | 확정된 결과를 발주기관에 제출 (사업자에도 통보) |
| 시정조치 | 시정조치 이행 | 사업자가 지적 사항을 조치하고 조치결과보고서 제출 |
| | 시정조치 확인 | 감리원이 조치 결과를 검증하고 확인 결과를 발주기관에 통보 |

## III. 비교 및 동향

### 가. 단계 감리 vs 상시 감리

| 비교 항목 | 단계 감리 ([[워터폴]] 기반) | 상시 감리 ([[Agile]] · 클라우드 기반) |
| --- | --- | --- |
| 투입 시점 | 요구정의·설계·종료 등 특정 단계 | 스프린트 단위로 상시 투입 |
| 점검 대상 | 단계별 산출물 문서 | 동작하는 SW와 코드, 백로그 |
| 결함 발견 | 마일스톤 도달 후 | CI/CD 파이프라인에서 조기 발견 (Shift-Left) |
| 점검 수단 | 문서 대조, 면담 | [[SAST]]·[[DAST]] 등 자동화 도구 연계 |

### 나. 동향

- **클라우드 네이티브 감리**: 디지털플랫폼정부 기조에 따라 [[MSA (Micro Service Architecture)\|MSA]]·[[컨테이너]]·CI/CD 점검 항목 강화
- **자동화 감리**: [[DevSecOps]] 파이프라인에 보안약점 진단 규칙을 내재화해 시정조치 여부를 실시간 확인
- **LLM 보조**: [[초거대 언어 모델\|LLM]]으로 제안서·요구사항 정의서 간 추적표를 자동 생성하고 체크리스트 초안 작성
- **전문 감리 분화**: [[빅데이터 감리\|데이터]]·[[인공지능 감리\|AI]] 등 영역별 감리 고도화
