# 페이지 교체 알고리즘 (Page Replacement Algorithm)

---

## I. 어떤 페이지를 내보낼 것인가, 페이지 교체 알고리즘의 개요

### 가. 정의

- 페이지 부재 시 빈 프레임이 없을 때 **메모리에 있는 페이지 중 내보낼 희생 페이지(Victim)를 고르는** [[메모리 관리]] [[알고리즘]]

### 나. 필요성 및 특징

| 구분 | 내용 |
| --- | --- |
| 필요성 | [[가상 메모리]] 환경에서 페이지 부재율과 디스크 I/O 최소화 |
| [[지역성]] 기반 | 과거 참조 패턴으로 가까운 미래 참조를 예측 |
| 비용 | Dirty 페이지는 디스크에 기록 후 교체해야 해 비용 큼 |
| 위험 | 부적절한 교체·프레임 부족 시 스래싱 |

---

## II. 동작 및 구성요소

### 가. 교체 과정

```mermaid
flowchart LR
    REQ["페이지 X 참조"] --> PF["페이지 부재"]
    PF --> ALG["교체 알고리즘<br/>희생 페이지 선택"]
    ALG --> OUT["희생 페이지<br/>Dirty면 디스크에 기록"]
    OUT --> IN["페이지 X 적재<br/>페이지 테이블 갱신"]
```

- 빈 프레임이 있으면 교체 없이 적재, 없을 때만 알고리즘으로 희생 페이지 선택

### 나. 주요 알고리즘

| 구분 | 요소 | 설명 |
| --- | --- | --- |
| 최적 | [[OPT]] (Belady) | 앞으로 가장 오래 쓰지 않을 페이지 교체, 미래를 알아야 해 구현 불가, 성능 비교의 하한 기준 |
| 순서 | [[FIFO]] | 가장 먼저 들어온 페이지 교체, 단순하나 자주 쓰는 페이지도 교체 |
| 시간 | [[LRU]] | 가장 오랫동안 참조하지 않은 페이지 교체, 시간 지역성 반영, 정확한 구현은 비용 큼 |
| 빈도 | [[LFU]] | 참조 횟수가 가장 적은 페이지 교체, 과거에 많이 쓴 페이지가 계속 남는 문제 |
| 근사 | [[NUR]] | 참조 비트·변경 비트 조합 (0,0)→(0,1)→(1,0)→(1,1) 순으로 교체 |
| | Clock (Second Chance) | 원형 [[Queue]]를 돌며 참조 비트가 1이면 0으로 바꾸고 넘어가고, 0이면 교체 |
| 이상 현상 | [[Belady's Anomaly]] | 프레임을 늘렸는데 부재가 증가 (FIFO 계열) |
| | 스래싱 | 교체에 실행보다 많은 시간을 쓰는 현상, 워킹 셋·PFF로 대응 |

---

## III. 비교 및 동향

### 가. 주요 알고리즘 비교

| 비교 항목 | FIFO | LRU | LFU | Clock (NUR) |
| --- | --- | --- | --- | --- |
| 기준 | 적재 순서 | 최근 참조 시점 | 참조 횟수 | 참조 비트 |
| 지역성 반영 | 없음 | 높음 | 일부 | LRU 근사 |
| 구현 비용 | 매우 낮음 | 높음 (스택·타임스탬프) | 높음 (카운터) | 낮음 (하드웨어 참조 비트) |
| Belady 모순 | 발생 가능 | 없음 (스택 알고리즘) | 없음 (스택 알고리즘) | 발생 가능 (FIFO로 퇴화) |
| 실제 OS | 거의 미사용 | 근사 형태로 사용 | 드묾 | 변형 형태로 널리 사용 |

### 나. 동향

- **OS의 LRU 근사**: Linux는 Active·Inactive 리스트 기반 LRU 근사에 이어 6.1부터 MGLRU(Multi-Gen LRU) 도입, ZFS는 ARC 캐시 사용
- **계층형 메모리 대응**: [[CXL]] 메모리·[[HBM]]·DRAM이 섞인 환경에서 교체 대신 핫·콜드 페이지를 계층 간 이동(승격·강등)
