# 가상 메모리 (Virtual Memory)

---

## I. 물리 메모리의 한계 극복, 가상 메모리의 개요

### 가. 가상 메모리의 정의

- 보조기억장치(Disk)의 일부를 주기억장치처럼 사용하여, [[프로세스]]가 **실제 RAM보다 큰 연속된 논리 주소 공간**을 사용할 수 있게 하는 [[메모리 관리]] 기법
- 프로세스 전체가 메모리에 없어도 필요한 부분만 적재(요구 페이징)하여 실행

### 나. 가상 메모리의 효과

| 구분 | 내용 |
| --- | --- |
| 용량 한계 극복 | RAM보다 큰 프로그램 실행 가능 |
| 다중 프로그래밍 효율 | 필요한 페이지만 적재하여 더 많은 프로세스를 동시에 유지 → [[CPU]] 이용률 향상 |
| 보호 및 공유 | 프로세스별 독립 주소 공간으로 침범 방지, 공유 라이브러리는 매핑으로 공유 |

---

- CPU의 논리 주소를 MMU가 TLB·페이지 테이블로 물리 주소로 변환하고, Valid 비트가 0이면 페이지 폴트로 OS가 디스크에서 페이지를 적재한 뒤 PTE를 갱신

### 나. 핵심 구성요소

| 구분 | 요소 | 설명 |
| --- | --- | --- |
| 주소 변환 | [[MMU(Memory Management Unit)\|MMU]] | [[논리 주소]]를 [[물리 주소]]로 변환하는 하드웨어 |
| | TLB | 최근 주소 변환 정보(PTE)를 저장하는 고속 [[캐시 메모리]] |
| | Page Table | 페이지 ↔ 프레임 매핑 정보, Valid 비트로 RAM 적재 여부 표시 |
| 할당 기법 | 페이징 | 고정 크기(Page/Frame) 분할, 내부 [[단편화]] 발생 |
| | [[세그멘테이션]] | 의미 단위의 가변 크기 분할, 외부 단편화 발생 |
| 운영 기법 | 요구 페이징 | 실제 참조되는 페이지만 적재 |
| | [[페이지 교체 알고리즘\|페이지 교체]] | 빈 프레임이 없을 때 교체 대상 선정 ([[LRU]], [[LFU]], [[FIFO]] 등) |
| 운영 이슈 | [[스레싱]] (Thrashing) | 프레임 부족으로 교체에 더 많은 시간을 쓰는 현상, 워킹 셋·PFF로 프레임 할당 조절 |

### 다. 페이지 부재(Page Fault) 처리 절차

1. **Page Fault 발생**: Valid 비트가 0이면 MMU가 [[인터럽트]]를 발생시켜 [[커널]] 모드로 전환
2. **페이지 탐색**: OS가 디스크(Backing Store)에서 해당 페이지 위치 확인
3. **Swap-out**: 빈 프레임이 없으면 교체 알고리즘으로 희생 페이지를 디스크로 내보냄 (Dirty 페이지만 기록)
4. **Swap-in**: 필요한 페이지를 빈 프레임에 적재
5. **재개**: 페이지 테이블을 갱신(Valid=1)하고 중단된 명령어를 다시 실행

## III. 비교 및 동향

### 가. 페이징 vs 세그멘테이션

| 비교 항목 | 페이징 | 세그멘테이션 |
| --- | --- | --- |
| 분할 단위 | 고정 크기 (Page/Frame) | 가변 크기 (논리 단위) |
| 단편화 | 내부 단편화 | 외부 단편화 |
| 주소 형태 | (페이지 번호, 오프셋) | (세그먼트 번호, 오프셋) |
| 보호·공유 | 페이지 단위라 상대적으로 복잡 | 논리 단위라 유리 |

- 두 기법을 결합한 페이지드 세그멘테이션도 있으나, x86-64 등 현대 OS는 세그먼트를 사실상 쓰지 않고(Flat) 페이징 중심으로 운영 ([[가상메모리의 페이징과 세그멘테이션]] 참고)

### 나. 동향

- **메모리 압축**: Linux·Android의 ZRAM/zswap, macOS·Windows의 압축 메모리로 디스크 스왑 I/O 감소
- **계층형 메모리 (Tiered Memory)**: DRAM – [[CXL]] 메모리 – NVMe SSD를 계층화하고 OS가 자주 쓰는 페이지를 빠른 계층으로 승격
