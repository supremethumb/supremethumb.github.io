# 이레이저 코딩 (Erasure Coding)

---

## I. 복제보다 적은 공간으로 장애에 견디는, 이레이저 코딩의 개요

### 가. 정의

- 데이터를 **k개 데이터 조각으로 나누고 m개 패리티 조각을 계산해 서로 다른 노드에 분산 저장**, 임의의 m개 조각이 사라져도 나머지 k개로 원본을 복원하는 데이터 보호 기법

### 나. 필요성 및 특징

| 구분 | 내용 |
| --- | --- |
| 필요성 | 3중 복제는 저장 효율 33%(3배 공간)로 대규모 스토리지 비용 부담 |
| 공간 효율 | k/(k+m), 예: RS(4,2) 67%, RS(10,4) 약 71%, RS(8,2) 80% |
| 장애 허용 | 조각 m개까지 동시 손실 허용 |
| 비용 | 인코딩 연산, 복구 시 k개 조각 읽기에 따른 네트워크·디스크 I/O 증가 |

---

## II. 구조 및 구성요소

### 가. 인코딩·복구 흐름 (RS 4+2)

```mermaid
flowchart LR
    D["원본 데이터"] --> K["데이터 조각 4개<br/>D1 · D2 · D3 · D4"]
    K -- "갈루아 필드 행렬 연산" --> P["패리티 2개<br/>P1 · P2"]
    K --> N["6개 노드에 분산 저장"]
    P --> N
    N -- "D3 · P1 노드 장애" --> R["남은 4개 조각으로<br/>역행렬 연산 → D3 · P1 복원"]
```

- k+m개 조각 중 아무 k개만 남아도 복원 가능 (MDS 부호)

### 나. 구성요소

| 구분 | 요소 | 설명 |
| --- | --- | --- |
| 기법 | 청킹 (Chunking) | 원본을 같은 크기 k개 조각으로 분할 |
| | 패리티 생성 | 갈루아 필드 GF(2⁸) 위 생성 행렬 곱으로 m개 패리티 계산 |
| | 디코딩 | 남은 k개 조각과 생성 행렬의 역행렬로 손실 조각 복원 |
| [[알고리즘]] | Reed-Solomon | 가장 널리 쓰는 MDS 부호, RS(6,3)·RS(10,4) 등 |
| | LRC (Local Reconstruction Code) | 그룹별 로컬 패리티를 추가해 단일 장애 복구 시 읽는 조각 수 감소 (Azure, Ceph 플러그인) |
| | Fountain Code | 패리티 수를 고정하지 않는 비율 무제한 부호, 패킷 손실 통신에 활용 |
| 가속 | Intel ISA-L 등 | SIMD 명령으로 인코딩·디코딩 가속 |
| 배치 | 장애 도메인 분산 | 조각을 서로 다른 디스크·노드·랙·가용 영역에 배치 |

---

## III. 비교 및 동향

### 가. 이레이저 코딩 vs 3중 복제

| 비교 항목 | 이레이저 코딩 | 3중 복제 |
| --- | --- | --- |
| 원리 | 분할 + 패리티 (k+m) | 전체 복사 3개 |
| 저장 효율 | 높음 (67~80% 수준) | 33% |
| 장애 허용 | m개 조각 | 복제본 2개 |
| 복구 | k개 조각 읽기 + 연산, 느림 | 복제본 복사, 빠름 |
| 쓰기·소규모 갱신 | 패리티 재계산으로 부담 | 단순 |
| 적합 데이터 | 콜드·웜 데이터, 오브젝트 스토리지, 백업 | 핫 데이터, 소규모 랜덤 쓰기 |
| 사례 | [[HDFS]] EC([[Hadoop 3.0]]~), Ceph, MinIO | HDFS 기본 복제, Ceph 복제 풀 |

### 나. 동향

- **클라우드 스토리지 기본 기법**: 대규모 오브젝트 스토리지·분산 파일시스템이 TCO 절감을 위해 EC를 기본 또는 선택 정책으로 제공
- **복구 비용 절감**: LRC·재생 부호(Regenerating Code)로 복구 트래픽 감소, SmartNIC·DPU로 인코딩 오프로드
