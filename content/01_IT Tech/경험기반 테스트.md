# 경험기반 테스트 (Experience-based Testing)

---

## I. 테스터의 지식과 직관 활용, 경험기반 기법의 개요

### 가. 정의

- 명세나 코드 구조 대신 **테스터의 경험·도메인 지식·과거 결함 이력을 바탕으로 테스트를 설계**하는 테스트 설계 기법군 (ISTQB: 오류 추정, 탐색적 테스트, 체크리스트 기반 테스트)

### 나. 특징

| 구분 | 내용 |
| --- | --- |
| 적용 상황 | 명세 부족·부정확, 일정 압박, 요구 변경이 잦은 환경 |
| 보완 관계 | 명세·구조 기반 기법이 놓친 예외 결함 탐지 |
| 의존성 | 결과 품질이 테스터 역량에 크게 좌우 |
| 한계 | 커버리지 측정·재현이 어려움 |

- 경험·결함 이력·불완전한 명세를 입력으로 오류 추정, 탐색적 테스트, 체크리스트 기법을 적용해 명세 기반 기법이 놓친 결함을 도출

### 나. 3대 기법

| 구분 | 요소 | 설명 |
| --- | --- | --- |
| 직관 기반 | 오류 추정 (Error Guessing) | 개발자가 실수하기 쉬운 부분(Null, 0 나누기, 경계 초과 등)을 예측해 케이스 도출, 결함 공격(Fault Attack) 포함 |
| 탐색 기반 | [[탐색적 테스트]] | 학습·설계·실행을 동시에 반복, 차터와 타임박스로 세션 관리 (SBTM) |
| 목록 기반 | 체크리스트 기반 테스트 | 과거 결함·품질 특성을 목록화해 누락 없이 점검, 경험이 적은 테스터의 가이드 |

## III. 비교 및 동향

### 가. 경험기반 vs 명세기반 vs 구조기반

| 비교 항목 | 경험기반 | [[블랙박스 테스트\|명세기반]] | [[화이트박스 테스트\|구조기반]] |
| --- | --- | --- | --- |
| 테스트 베이시스 | 테스터 경험·결함 이력 | 요구사항·명세 | 소스 코드 구조 |
| 대표 기법 | 오류 추정, 탐색적, 체크리스트 | 동등 분할, 경계값, 결정 테이블 | 구문·결정·조건 커버리지 |
| 커버리지 측정 | 어려움 | 요구사항 기준 | 코드 기준 |
| 강점 | 예상 밖 결함 발견 | 체계적·재현 가능 | 미실행 코드 식별 |

### 나. 동향

- 정형 회귀 검증은 자동화에 맡기고 사람은 업무 맥락·UX·예외 상황 탐색에 집중하는 역할 분담
- 이슈 이력을 분석해 탐색할 위험 영역과 차터를 추천하는 AI 보조 도구 등장
- 애자일 스프린트 말미에 팀 전체가 참여하는 짧은 탐색 세션 활용
