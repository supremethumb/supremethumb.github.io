# 거리 벡터 알고리즘 (Distance Vector Algorithm)

---

## I. 인접 라우터 간 주기적 정보 교환, 거리 벡터 알고리즘의 개요

### 가. 거리 벡터 알고리즘의 정의

- 인접해 있는 [[라우터]] 간에 거리(Distance)와 방향(Vector) 정보를 주기적으로 교환하여 자신의 라우팅 테이블을 갱신하고 최적 경로를 결정하는 동적 [[라우팅 알고리즘]].
- 전체 네트워크 토폴로지를 알지 못하고, 이웃 라우터의 정보에 의존하여 경로를 설정하는 방식.
### 나. 핵심 키워드 (암기법: 거리수베)

- 벨만-포드(Bellman-Ford) [[알고리즘]], 인접 라우터(Neighbor), 주기적 교환(30초), Hop Count, RIP, IGRP, 무한 계수 문제(Count to Infinity).

---

### 나. 주요 특징 및 문제점

| 구분 | 내용 | 비고 |
| --- | --- | --- |
| 동작 원리 | - 인접 라우터와만 라우팅 테이블 전체를 교환.<br>- 주기적(수시로) 업데이트 (예: RIP는 30초마다). | 거리수베 |
| 경로 결정 | - Bellman-Ford 알고리즘 사용.<br>- Hop Count를 메트릭으로 사용하여 최단 경로 산출. |  |
| 문제점 | - 느린 수렴(Convergence): 변화 발생 시 전체 전파 느림.<br>- Count to Infinity: 라우팅 루프 발생 가능성. |  |
| 해결책 | - Split Horizon, Route Poisoning, Hold-down Timer 등. | (보완 기술) |

## III. 거리 벡터(DV)와 링크 상태(LS) 라우팅 프로토콜 비교

### 가. 비교표 (암기법: 거리수베 vs 링오이다)

| 비교 항목 | 거리 벡터 (Distance Vector) | 링크 상태 (Link State) |
| --- | --- | --- |
| 핵심 알고리즘 | Bellman-Ford (벨만-포드) | [[다익스트라 알고리즘|Dijkstra]] (다익스트라) |
| 정보 교환 대상 | 인접 라우터 (Neighbors) | 모든 라우터 (Flooding) |
| 교환 시기 | 주기적 (30초 등) | 이벤트 발생 시 (변화 시) |
| 토폴로지 인지 | 부분적 인지 (이웃만 앎) | 전체 토폴로지 인지 (Global View) |
| 대표 [[프로토콜]] | RIP, IGRP | OSPF, IS-IS |
| 규모 | 소규모 네트워크 적합 (Hop 제한) | 대규모 네트워크 적합 |

### 나. 결론 및 고려사항

- 거리 벡터는 구현이 간단하고 메모리를 적게 차지하나, 수렴 속도가 느리고 루프 발생 위험이 있어 소규모 망에 적합함.
- 대규모 망에서는 OSPF(링크 상태)를 주로 사용하며, 최근에는 [[SDN(Software Defined Network)|SDN]] 등의 중앙 집중형 제어로 발전하는 추세임.
