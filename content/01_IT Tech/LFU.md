# LFU (Least Frequently Used)

---

## I. 참조 횟수로 고르는, LFU의 개요

### 가. 정의

- 교체가 필요할 때 **참조 횟수(Frequency)가 가장 적은 페이지·캐시 블록을 교체**하는 [[페이지 교체 알고리즘]]

### 나. 특징

| 구분 | 내용 |
| --- | --- |
| 빈도 반영 | 오래도록 자주 쓰이는 데이터를 보존, 일회성 스캔에 강함 |
| 카운터 유지 | 항목마다 참조 횟수 카운터 필요 |
| 과거 편향 | 예전에 많이 쓰였지만 지금은 안 쓰는 데이터가 높은 카운트로 계속 남음 |
| 신규 불리 | 막 적재된 데이터는 카운트가 낮아 곧바로 교체되기 쉬움 |
| 스택 알고리즘 | 프레임 수와 무관한 우선순위 기반이라 [[Belady's Anomaly]] 없음 |

---

## II. 동작 구조 및 구성요소

### 가. 교체 동작

```mermaid
flowchart LR
    REQ["Page E 요청<br/>(미스, 프레임 가득)"] --> CMP["카운트 비교<br/>A:5, B:1, C:8, D:3"]
    CMP --> EV["최소 카운트 B 교체"]
    EV --> IN["E 적재, 카운트 1"]
```

- 참조될 때마다 카운트를 1 늘리고, 교체 시 카운트가 가장 작은 항목을 내보냄

### 나. 구성요소

| 구분 | 요소 | 설명 |
| --- | --- | --- |
| 상태 | 참조 카운터 | 항목별 참조 횟수 |
| 자료구조 | 최소 힙 | 최소 빈도 항목 탐색 O(log N) |
| | 빈도별 연결 리스트 | 같은 빈도끼리 묶어 O(1) 갱신·교체 |
| 정책 | 동률 처리 | 카운트가 같으면 가장 오래전에 참조된 항목(LRU) 교체 |
| 보완 | 에이징 (Aging) | 주기적으로 카운트를 절반 등으로 감소시켜 과거 편향 완화 |
| | LRFU | 최근성과 빈도를 가중 결합한 값으로 교체 |

## III. 비교 및 동향

### 가. LFU vs LRU

| 비교 항목 | LFU | [[LRU]] |
| --- | --- | --- |
| 교체 기준 | 참조 횟수 | 마지막 참조 시점 |
| 강점 | 장기 인기 데이터 보존, 스캔 내성 | 최근 작업 집합 변화에 빠르게 적응 |
| 약점 | 과거 편향, 신규 항목 불리 | 대용량 순차 스캔 시 캐시 오염 |
| 구현 | 카운터·정렬 비용 | 해시 + 이중 연결 리스트로 O(1) |

### 나. 동향

- **W-TinyLFU**: Count-Min Sketch로 적은 메모리로 빈도를 근사하고 작은 LRU 윈도로 최근성 보완, Java Caffeine 캐시가 채택
- **Redis LFU**: 4.0부터 `allkeys-lfu`·`volatile-lfu` 제공, 키당 8비트 로그 확률 카운터와 감쇠 시간으로 빈도 근사
- **적응형 정책**: ARC 등은 최근성 리스트와 빈도 리스트 크기를 워크로드에 따라 자동 조절
