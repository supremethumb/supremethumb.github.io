### 나. GoF 23개 패턴

| 분류 | 패턴 | 핵심 의도 |
| :--- | :--- | :--- |
| **생성 (5)** | [[Singleton (전역 인스턴스)\|Singleton]] | 인스턴스를 하나만 만들고 전역 접근점 제공 |
| | [[Factory Method (생성 위임)\|Factory Method]] | 객체 생성을 서브클래스에 위임 |
| | Abstract Factory | 관련 객체군을 생성하는 인터페이스 제공 |
| | Builder | 복잡한 객체의 생성 과정과 표현 분리 |
| | Prototype | 기존 객체를 복제하여 생성 |
| **구조 (7)** | [[어댑터 패턴\|Adapter]] | 호환되지 않는 인터페이스 변환 |
| | Decorator | 객체에 동적으로 기능 추가 |
| | [[Proxy Pattern\|Proxy]] | 대리 객체로 접근 제어·지연 로딩 |
| | Facade | 복잡한 서브시스템에 단일 인터페이스 제공 |
| | Composite | 단일·복합 객체를 트리로 구성해 동일하게 취급 |
| | Bridge | 추상과 구현을 분리해 독립적으로 확장 |
| | Flyweight | 공통 상태를 공유해 메모리 절감 |
| **행위 (11)** | [[Strategy (알고리즘 교체)\|Strategy]] | 알고리즘을 캡슐화해 런타임에 교체 |
| | [[Observer (상태 변화 통지)\|Observer]] | 상태 변화를 구독자에게 자동 통지 |
| | State | 상태에 따라 행동을 바꾸도록 상태를 클래스화 |
| | Command | 요청을 객체로 캡슐화 (큐잉, 로깅, Undo) |
| | Template Method | 알고리즘 골격은 상위, 세부 단계는 하위 클래스 |
| | Iterator | 내부 구조 노출 없이 순차 접근 |
| | Chain of Responsibility | 처리 가능한 객체를 만날 때까지 요청 전달 |
| | Mediator | 중재자를 통해 객체 간 직접 참조 축소 |
| | Memento | 캡슐화를 지키며 상태 저장·복원 |
| | Interpreter | 문법 표현과 해석기 정의 |
| | Visitor | 구조 변경 없이 새 연산을 외부에 추가 |

## III. 적용 시 유의사항 및 최신 동향

### 가. 적용 시 유의사항

- **과도한 설계 경계**: 단순한 문제에 패턴을 억지로 적용하면 가독성·유지보수성이 오히려 저하
- **원칙 이해 우선**: 패턴은 [[객체지향 설계 원리\|SOLID]]를 구현하는 수단 → 각 패턴이 어떤 원칙(OCP, DIP 등)을 만족하는지 이해 (예: Strategy → OCP)

### 나. 최신 동향

- **프레임워크 내재화**: Spring 등에서 DI·IoC, 이벤트 기반 통신이 기본 제공되어 Factory·Strategy·Observer 등이 프레임워크 기능으로 흡수
- **분산 환경 패턴 확장**: [[MSA (Micro Service Architecture)\|MSA]]·[[클라우드 네이티브]] 환경에서 [[SAGA패턴\|Saga]], [[서킷브레이커\|Circuit Breaker]], API Gateway 등 분산 패턴으로 확장
- **AI 코딩 지원**: 생성형 AI가 상황에 맞는 패턴 추천과 보일러플레이트 코드 생성을 지원
