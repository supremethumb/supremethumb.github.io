# McCabe 회전 복잡도 (McCabe Cyclomatic Complexity)

---

## I. 소스 코드 제어 흐름 기반의 복잡도 정량 지표, McCabe 회전 복잡도의 개요

소프트웨어 모듈의 논리적 복잡도를 정량적으로 측정하기 위해 프로그램의 제어 흐름 그래프(Control Flow Graph, CFG)를 바탕으로 선형적으로 독립적인 기본 실행 경로의 수를 산출하는 정적 분석 메트릭이다.

| 구분 | 주요 내용 |
| --- | --- |
| **개념** | 제어 흐름도의 노드(Node), 간선(Edge), 분기 조건(Predicate)의 개수를 기반으로 모듈의 논리적 복잡도를 계산하는 소프트웨어 척도 |
| **등장 배경** | 모듈의 구조적 복잡도를 객관적으로 수치화하여 코드 리뷰와 리팩토링 기준을 수립하고, 화이트박스 테스팅 시 필요한 최소 테스트 케이스 수를 산정 필요 |
| **핵심 특징** | 기본 경로 테스트(Basis Path Testing)의 상한선 제공, $V(G) \le 10$ 권장 지표 준수를 통한 결함 예방 및 유지보수성 향상 |

---

## II. 회전 복잡도의 계산 공식 및 분석 메커니즘

### 가. 제어 흐름 그래프(CFG)와 복잡도 계산 개념도

```mermaid
flowchart TD
    Start((1: 시작)) --> Cond1{"2: if 조건문 (P1)"}
    
    Cond1 -->|True| Block1["3: 처리 블록 A"]
    Cond1 -->|False| Cond2{"4: while 반복문 (P2)"}
    
    Block1 --> Merge1((5: 병합 노드))
    Cond2 -->|True (반복)| Block2["6: 처리 블록 B"]
    Block2 --> Cond2
    Cond2 -->|False (탈출)| Merge1
    
    Merge1 --> End((7: 종료))
```

위 제어 흐름도에서 분기 노드 $P = 2$ (`if`, `while`)이므로, 회전 복잡도 $V(G) = P + 1 = 3$이 되며, 이 모듈을 완전히 검증하기 위한 선형 독립 경로는 총 3개이다.

### 나. 회전 복잡도 산출 공식

회전 복잡도 $V(G)$는 그래프 이론에 기반하여 아래 세 가지 공식 중 어느 것을 사용해도 동일한 결과값으로 도출된다.

| 산출 방식 | 계산 공식 | 세부 설명 및 변수 의미 |
| --- | --- | --- |
| **조건 분기 기반** | $V(G) = P + 1$ | $P$: 제어 흐름 그래프 내의 조건 분기 노드(Predicate Node, `if`, `while`, `case` 등)의 수 |
| **간선/노드 기반** | $V(G) = E - N + 2$ | $E$: 제어 흐름 간선(Edge)의 수, $N$: 실행 블록 및 분기를 나타내는 노드(Node)의 수 |
| **영역(Region) 기반** | $V(G) = \text{면의 수}$ | 제어 흐름 그래프의 간선으로 둘러싸인 닫힌 영역(Bounded Region)의 수 + 1 (외부 개방 영역) |

## III. 회전 복잡도 평가 기준 및 실무 적용 동향

### 가. 복잡도 $V(G)$ 수준별 평가 기준 및 관리 방안

| 복잡도 수치 $V(G)$ | 프로그램 상태 | 구조적 위험도 및 조치 가이드라인 |
| --- | --- | --- |
| **1 ~ 10** | 단순하고 구조적인 모듈 | 결함 발생률 낮음, 테스트 용이, 높은 유지보수성 (**권장 기준**) |
| **11 ~ 20** | 다소 복잡한 모듈 | 중간 수준의 위험, 코드 리뷰 집중 및 지속적인 모니터링 필요 |
| **21 ~ 50** | 매우 복잡한 모듈 | 구조적 위험성 매우 높음, **메서드 분할 및 코드 리팩토링 적극 권장** |
| **50 초과** | 비구조적 (스파게티 코드) | 테스트 및 유지보수 불가 수준, **모듈 전면 재작성 및 아키텍처 재설계 필수** |

### 나. 실무 활용 동향 및 한계점 극복

* **CI/CD 파이프라인 품질 게이트(Quality Gate) 연계**: SonarQube 등 정적 분석 도구와 연계하여 PR(Pull Request) 시 특정 메서드의 $V(G) > 10$ 초과 시 자동 빌드 실패 또는 리팩토링 경고를 부여하는 품질 통제가 보편화됨.
* **객체지향 및 데이터 복잡도 보완 메트릭 병행**: 제어 흐름만 반영하고 데이터 구조나 상속 깊이를 고려하지 못하는 한계를 보완하기 위해, 인지 복잡도(Cognitive Complexity) 및 C&K 객체지향 메트릭(WMC, CBO)과 결합하여 종합적인 코드 품질을 평가함.
