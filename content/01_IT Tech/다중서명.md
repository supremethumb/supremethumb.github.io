# 다중서명 (Multi-Signature)

---

## I. 권한 분산으로 단일 키 위험 제거, 다중서명의 개요

### 가. 정의

- 하나의 거래를 승인할 때 **미리 지정한 n개의 키 중 m개 이상의 서명(m-of-n)이 있어야 유효**하도록 하는 서명 방식

### 나. 필요성 및 특징

| 구분 | 내용 |
| --- | --- |
| SPOF 제거 | 키 하나가 탈취돼도 단독으로 자산 이동 불가 |
| 키 분실 대비 | n-m개까지 키를 잃어도 자산 사용 가능 |
| 권한 분산 | 기관 결재·DAO 거버넌스 등 다자 승인 절차 구현 |
| m-of-n 구조 | 2-of-3, 3-of-5 등 정책을 스크립트·스마트 컨트랙트로 정의 |

- 거래 요청에 대해 서명자별 개별 서명을 모아, 임계치 m을 넘으면 스크립트 또는 스마트 컨트랙트가 [[트랜잭션]] 실행

### 나. 구성요소

| 구분 | 요소 | 설명 |
| --- | --- | --- |
| 합의 구조 | m-of-n 정책 | n개 지정 키 중 m개 이상 서명 시 승인 |
| 서명 방식 | ECDSA | 비트코인·이더리움의 타원곡선 서명, 서명을 개별 검증 |
| | Schnorr (MuSig) | 서명의 선형성으로 여러 서명을 하나로 집계, 크기 축소 |
| 구현 | 스크립트 기반 | 비트코인 P2SH·P2WSH의 `OP_CHECKMULTISIG` |
| | 컨트랙트 기반 | 이더리움 Safe 등 스마트 컨트랙트 지갑 |
| 응용 | 계정 추상화 | ERC-4337 스마트 계정으로 다중서명·소셜 복구 결합 |

## III. 비교 및 동향

### 가. 다중서명 vs 임계치 서명(TSS)

| 비교 항목 | 다중서명 (Multisig) | 임계치 서명 (Threshold Signature) |
| --- | --- | --- |
| 키 구조 | 서명자별 독립 개인키 n개 | 하나의 개인키를 MPC로 분할 생성·보관 |
| 처리 위치 | 온체인에서 서명 수 검증 | 오프체인에서 서명 결합 후 단일 서명 제출 |
| 데이터 크기 | 서명자 수에 비례 | 단일 서명과 동일 |
| 프라이버시 | 서명자·정책이 체인에 노출 | 일반 단일 서명과 구분 불가 |
| 호환성 | 체인별 스크립트·컨트랙트 지원 필요 | 단일 서명을 지원하는 체인 전반 |

### 나. 동향

- **기관 커스터디**: 거래소·수탁기관의 콜드월렛 승인 정책에 다중서명·MPC 병행 적용
- **계정 추상화 확산**: ERC-4337 스마트 월렛에서 지출 한도·소셜 복구와 결합
- **Taproot(MuSig2)**: 비트코인에서 집계 서명으로 다중서명의 수수료·프라이버시 단점 완화
