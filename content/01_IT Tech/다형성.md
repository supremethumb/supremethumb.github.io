# 다형성 (Polymorphism)

---
## I. 하나의 메시지, 다양한 응답: 다형성의 개요

### 가. 정의

- 동일한 메시지 전송(메서드 호출)에 대해 각 객체가 자신의 타입에 맞는 고유한 행위로 응답할 수 있는 객체지향 설계 특성

### 나. 특징 및 설계 이점

| 구분 | 내용 |
| --- | --- |
| 유연성 및 확장성 | 상위 인터페이스를 통해 구체 클래스에 구애받지 않고 유연하게 새로운 클래스 추가 가능 |
| 결합도 감소 | 클라이언트 코드가 구현체가 아닌 추상화에 의존하므로 모듈 간 결합도 완화 ([[객체지향 설계 원리\|DIP]]) |
| OCP 원칙 지원 | 기존 코드를 수정하지 않고 새로운 기능 확장을 가능하게 하는 핵심 기반 메커니즘 |
| 재사용성 증대 | 공통된 인터페이스 기반으로 다형적 컬렉션 및 제네릭 알고리즘 재사용 촉진 |

* 다형성은 바인딩(Binding)이 결정되는 시점에 따라 컴파일 타임에 결정되는 **정적 바인딩(오버로딩)**과 런타임에 결정되는 **동적 바인딩(오버라이딩)**으로 구분됨.

### 나. 다형성의 4대 분류 및 구현 메커니즘

| 분류 | 구현 방식 | 세부 설명 |
| --- | --- | --- |
| **포함 다형성 (Inclusion)** | 서브타이핑 / 오버라이딩 | 상속 또는 인터페이스 구현을 통해 상위 타입 참조 변수가 하위 객체를 참조하는 동적 다형성 |
| **매개변수 다형성 (Parametric)** | 제네릭 (Generics) / 템플릿 | 타입을 매개변수화하여 하나의 코드가 여러 데이터 타입을 안전하게 처리하도록 일반화 |
| **오버로딩 다형성 (Ad-hoc)** | 메서드 오버로딩 | 동일한 메서드명이 매개변수의 타입이나 개수에 따라 컴파일 시점에 정적으로 바인딩 |
| **강제 다형성 (Coercion)** | 형 변환 (Type Casting) | 암시적 또는 명시적 타입 변환을 통해 다른 타입의 인자를 수용하여 처리 |

## III. 오버로딩 vs 오버라이딩 비교 및 설계 연계

### 가. 오버로딩(Overloading)과 오버라이딩(Overriding) 비교

| 비교 항목 | 오버로딩 (Overloading) | 오버라이딩 (Overriding) |
| --- | --- | --- |
| **개념** | 같은 이름의 메서드를 다수 정의 | 상위 [[클래스]] 메서드를 하위에서 재정의 |
| **바인딩 시점** | **정적 바인딩** (Compile-time) | **동적 바인딩** (Run-time) |
| **조건** | 메서드명 동일, **매개변수 다름** | 메서드명, **매개변수, 리턴 타입 동일** |
| **적용 범위** | **동일 클래스** 내 | **상속 관계** (상위-하위 클래스) |

### 나. 최신 동향 및 설계 원칙 연계

- **[[객체지향 설계 원리\|SOLID]] 핵심 기반**: 다형성은 기존 코드를 고치지 않고 기능을 확장(OCP)하며 하위 타입이 상위 타입을 대체(LSP)하는 객체지향 설계의 핵심 엔진
- **함수형 프로그래밍과의 융합**: 모던 언어(Java, Kotlin, TypeScript)에서 람다식 및 고차 함수를 활용한 일급 객체 기반 경량 다형성 기법 일반화
- **DI 프레임워크와의 결합**: Spring IoC 컨테이너 등에서 인터페이스 기반 다형성을 이용해 런타임에 빈(Bean) 객체를 동적으로 주입하여 느슨한 결합 달성
