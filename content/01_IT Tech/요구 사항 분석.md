# 요구 사항 분석 (Requirements Analysis)

---

## I. 수집된 요구를 모델로 구조화, 요구 사항 분석의 개요

### 가. 정의

- 도출된 요구사항의 **모순·누락·모호성을 제거하고 분류·우선순위화·타당성 검토를 거쳐 분석 모델로 구조화**하는 [[요구 공학]]의 핵심 단계

### 나. 필요성

| 구분 | 내용 |
| --- | --- |
| 충돌 해소 | 이해관계자 간 상충 요구 조율, 우선순위 합의 |
| 타당성 확보 | 기술·경제·법·운영·일정 제약 하의 구현 가능성 검토 |
| 설계 기준 | 분석 모델이 설계 단계의 기준선 제공 |
| 방법 | 모델링 중심, 분할 정복과 [[추상화]] |

---

## II. 분석 절차 및 기법

### 가. 분석 절차

```mermaid
flowchart LR
    IN["도출된 요구사항<br/>(인터뷰 · 워크숍 결과)"] --> C1["1. 분류 · 우선순위"]
    C1 --> C2["2. 타당성 분석 (TELOS)"]
    C2 --> C3["3. 분석 모델링"]
    C3 --> C4["4. 충돌 해결 · 협상"]
    C4 --> OUT["분석 모델 · 자료 사전<br/>→ 요구사항 명세"]
```

- 기능·비기능으로 분류하고 타당성을 검토한 뒤 [[데이터 흐름도|DFD]]·[[UML]]로 모델링하고, 이해관계자 협상으로 일관된 분석 결과를 확정

### 나. 분석 기법

| 구분 | 요소 | 설명 |
| --- | --- | --- |
| 구조적 분석 | [[데이터 흐름도\|DFD]] | 프로세스·데이터 흐름·저장소·외부 [[엔티티]]로 기능 모델링 (버블 차트) |
| | [[자료 사전]] (DD) | DFD 데이터 항목의 구성과 의미 정의 |
| | 소단위 명세 (Mini-Spec) | 최하위 프로세스의 처리 논리를 구조적 언어·의사코드로 기술 |
| | 상태 전이도 (STD) | 이벤트에 따른 상태 변화로 제어 흐름 표현 |
| [[객체지향]] 분석 | [[유즈케이스 다이어그램]] | 액터 관점의 기능 요구와 시스템 경계 |
| | [[클래스 다이어그램]] | 객체의 속성·오퍼레이션·관계로 정적 구조 표현 |
| 분석 기법 | 타당성 분석 (TELOS) | Technical·Economic·Legal·Operational·Schedule |
| | 요구사항 할당 | 분석된 요구를 SW·HW·인력 등 구성요소에 배분 |
| | 우선순위화 | MoSCoW, Kano 모델 등 |

---

## III. 비교 및 동향

### 가. 구조적 분석 vs 객체지향 분석

| 비교 항목 | 구조적 분석 | 객체지향 분석 |
| --- | --- | --- |
| 관점 | 기능과 데이터 흐름 | 객체와 상호작용 |
| 도구 | DFD, DD, Mini-Spec, ERD, STD | UML (유즈케이스, 클래스, [[순차 다이어그램\|시퀀스]]) |
| 분석 단위 | 프로세스 | 객체 (상태 + 행위의 [[캡슐화]]) |
| 재사용성 | 낮음 (기능 종속) | 높음 (상속·[[다형성]]) |
| 적합 시스템 | 데이터 처리 중심 시스템 | 변경이 잦고 상호작용이 복잡한 시스템 |

### 나. 동향

- LLM으로 자연어 요구사항의 모호성·불일치를 탐지하고 모델 초안 생성
- [[Agile]] 환경에서 에픽·사용자 스토리 백로그로 스프린트마다 점진 분석
- 항공·국방·자동차 등 복잡 시스템에서 SysML 기반 MBSE(모델 기반 시스템 공학) 확산
