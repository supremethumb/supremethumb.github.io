# AI 시스템 테스트 (AI System Testing)

---

## I. 확률적 시스템을 검증하는, AI 시스템 테스트의 개요

### 가. 정의

- 데이터로 학습해 확률적 결과를 내는 AI 시스템의 **성능·강건성·공정성·설명가능성·안전성을 검증**하는 품질 보증 활동

### 나. 필요성 및 특징

| 구분 | 내용 |
| --- | --- |
| 오라클 문제 | 입력별 정답을 미리 정하기 어려워 기존 [[테스트 오라클]] 적용 곤란 |
| 비결정성 | 학습 데이터·난수·샘플링에 따라 결과가 달라짐 |
| 새로운 위험 | 편향, [[할루시네이션]], 적대적 입력, 데이터 드리프트 |
| 규제 | EU AI Act 등 고위험 AI의 시험·문서화 요구 강화 |
| 전 주기 검증 | 데이터 → 모델 → 시스템 → 운영까지 반복 검증 |

---

## II. 테스트 수명주기 및 핵심 기법

### 가. 수명주기 개념도

```mermaid
flowchart LR
    D["데이터 테스트<br/>품질, 편향, 누수 점검"] --> M["모델 테스트<br/>성능, 강건성, 공정성"]
    M --> S["시스템 테스트<br/>API 연동, 섀도·카나리 배포"]
    S --> O["운영 테스트<br/>드리프트·성능 모니터링"]
    O -. "재학습 (Continuous Training)" .-> D
```

- [[MLOps]]·[[LLMOps]] 파이프라인에서 데이터·모델·시스템·운영 단계를 지속적으로 검증

### 나. 핵심 기법

| 구분 | 요소 | 설명 |
| --- | --- | --- |
| AI 특화 | 메타모픽 테스트 | 입력 변환과 출력 변화 사이의 관계(Metamorphic Relation)로 오라클 문제 완화 (예: 이미지 밝기 변화에도 분류 동일) |
| | 적대적 테스트 | 조작된 입력으로 강건성·보안성 평가 ([[머신러닝 학습과정에서의 적대적 공격]]) |
| | 뉴런 커버리지 | 신경망 뉴런 활성화 비율로 테스트 충분성 측정하는 [[화이트박스 테스트]] (결함 탐지력과의 상관은 논쟁 중) |
| 데이터 | 데이터 검증 | 분포 차이, 레이블 오류, 학습-테스트 누수, 인구통계 편향 진단 |
| 성능 | 분류·회귀 지표 | [[혼동행렬]] 기반 정밀도·재현율·F1, RMSE 등 |
| 배포 | 섀도·카나리 테스트 | 실제 트래픽을 신규 모델에 복제·일부 전달해 영향 없이 비교 |
| 신뢰성 | 공정성·설명가능성 | 집단별 성능 차이 점검, SHAP·[[LIME]]으로 근거 확인 ([[XAI]]) |
| LLM | 평가·레드팀 | 벤치마크, LLM-as-a-Judge, [[AI 레드팀(Red team) 테스트\|레드팀]] |
| 운영 | 드리프트 탐지 | 입력 분포 변화(데이터 드리프트)·입출력 관계 변화(컨셉 드리프트) 추적 |

## III. 비교 및 동향

### 가. 전통 SW 테스트 vs AI 시스템 테스트

| 비교 항목 | 전통 SW 테스트 | AI 시스템 테스트 |
| --- | --- | --- |
| 동작 근거 | 코드·규칙 (연역적) | 데이터·모델 (귀납적) |
| 결과 | 결정적 | 확률적 |
| 오라클 | 명확 | 정의 어려움 |
| 품질 속성 | 기능 정확성, 성능, 보안 | 강건성, 공정성, 설명가능성, 재현성 |
| 기법 | [[단위 테스트]], [[통합 테스트]], 경계값 분석 | 메타모픽·적대적 테스트, 데이터 검증 |
| 참고 표준 | ISO/IEC/IEEE 29119 | ISO/IEC TR 29119-11(AI 시스템 테스트 지침), ISO/IEC TS 42119-2 |

### 나. 동향

- **LLM 평가 자동화**: LLM-as-a-Judge, 자동 레드팀 도구로 대규모 평가를 자동화하고 사람 평가로 보정
- **AI 테스트 표준화**: AI 시스템 테스트 표준([[ISO IEC TS 42119-2]])과 [[인공지능 경영시스템|ISO/IEC 42001]] 기반 관리 체계, 국내 [[AI 신뢰성 인증]]과 연계
