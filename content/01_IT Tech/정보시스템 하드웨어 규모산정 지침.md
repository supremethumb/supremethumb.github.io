# 정보시스템 하드웨어 규모산정 지침

---

## I. 서버·스토리지 용량을 근거 있게 정하는, HW 규모산정 지침의 개요

### 가. 정의

- 정보시스템 구축 시 **업무량·성능 요구를 바탕으로 서버(CPU·메모리)와 스토리지의 적정 용량을 산정하는 방법과 기준**을 정한 TTA 표준 지침 (TTAK.KO-10.0292)

### 나. 필요성 및 특징

| 구분 | 내용 |
| --- | --- |
| 필요성 | 과다 산정에 따른 예산 낭비, 과소 산정에 따른 성능 저하 방지 |
| 객관성 | 공공 정보화 사업 예산·발주의 산정 근거 제공 |
| 수식 계산 원칙 | 업무량 기반 수식으로 산정하고 보정계수 적용 |
| 성능 지표 | tpmC, SPECint_rate 등 공인 벤치마크 지표 활용 |

---

## II. 산정 절차 및 구성요소

### 가. 산정 절차

```mermaid
flowchart LR
    A["요구 분석<br/>사용자 수, 트랜잭션, 데이터 증가"] --> B["산정 방식 선택<br/>수식계산·참조·시뮬레이션"]
    B --> C["기본 용량 산출<br/>CPU, 메모리, 디스크"]
    C --> D["보정계수 적용<br/>피크, 여유율, 클러스터"]
    D --> E["최종 규모<br/>서버, 스토리지"]
```

- 업무량을 성능 지표로 환산해 기본 용량을 구한 뒤 피크·여유율 등 보정계수를 곱해 최종 규모를 확정

### 나. 구성요소

| 구분 | 요소 | 설명 |
| --- | --- | --- |
| 산정 방식 | 수식계산법 | 업무량을 표준 수식에 대입 (원칙) |
| | 참조법 | 유사 시스템 규모를 참조 |
| | 시뮬레이션법 | 부하 시험 결과로 산정 |
| 성능 지표 | tpmC (TPC-C) | 분당 트랜잭션 처리량, OLTP·DB 서버 CPU 산정 |
| | SPECint_rate | 정수 연산 처리량, 웹·애플리케이션 서버 산정 |
| 보정계수 | 피크타임 보정 | 평균 대비 최대 부하 시간대 반영 |
| | 목표 CPU 사용률 | 예: 70% 목표 → 1/0.7 보정 |
| | 클러스터 보정 | 노드 장애 시 남은 노드가 부하를 감당하도록 보정 |
| 스토리지 | 포맷·[[RAID]] 보정 | 파일시스템 손실, RAID 패리티·미러 오버헤드, 증가율 |

## III. 온프레미스·클라우드 비교 및 동향

### 가. 온프레미스 vs 클라우드 규모산정

| 구분 | 온프레미스 | 클라우드 (IaaS) |
| --- | --- | --- |
| 단위 | 물리 코어, 메모리 | vCPU, vRAM, 인스턴스 유형 |
| 보정 | 클러스터·[[다중화]] 보정 | [[가상화]] 오버헤드 보정 (예: 10~20%) |
| 기준 | 최대 피크 기준 정적 [[프로비저닝]] | 기준 용량 + 오토스케일링 |
| 비용 | 초기 투자(CapEx) | 사용량 기반(OpEx) |

### 나. 동향

- **AI 인프라 산정**: 학습·추론용 [[GPU]]·[[NPU]]는 연산량(FLOPS)·메모리 용량·토큰 처리량 기준 산정 방법 필요
- **클라우드 네이티브 산정**: [[MSA (Micro Service Architecture)|MSA]]·[[컨테이너]] 환경은 Pod 요청·제한값과 오토스케일링 임계치로 용량 설계
- **사업비 연계**: 산정 결과를 [[ISMP]] 사업비, 클라우드 이용료 산정과 연결
