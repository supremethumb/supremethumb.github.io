# 블랙박스 테스트 (Black-box Test)

---

## I. 내부를 보지 않는 명세 기반 검증, 블랙박스 테스트의 개요

### 가. 정의

- 내부 구조를 보지 않고 **요구사항 명세를 근거로 입력에 대한 출력이 올바른지 확인**하는 명세 기반 테스트 설계 기법

### 나. 특징

| 구분 | 내용 |
| --- | --- |
| 관점 | 사용자·외부 관점의 기능 검증 |
| 근거 | 요구사항 명세·기획서에서 케이스 도출 |
| 코드 지식 | 불필요, 개발자와 독립적인 테스터도 수행 가능 |
| 한계 | 미실행 코드·내부 경로 결함은 찾기 어려움 |

- 명세에서 테스트 케이스를 도출해 입력을 주고, 실제 출력과 기대 결과를 비교해 결함을 식별

### 나. 테스트 설계 기법

| 구분 | 요소 | 설명 |
| --- | --- | --- |
| 데이터 범위 | 동등 분할 | 입력을 같은 처리를 받는 그룹으로 나눠 대표값 하나씩 시험 |
| | 경계값 분석 | 경계와 경계 바로 안·밖 값 시험 (오류가 경계에 집중) |
| 논리 · 조건 | 결정 테이블 | 조건 조합과 행위를 표로 정리해 복잡한 규칙 검증 |
| | 원인-결과 그래프 | 입력(원인)과 출력(결과)의 논리 관계를 그래프로 표현해 결정 테이블 도출 |
| | 상태 전이 | 상태·이벤트·전이에 따른 동작 검증 ([[상태 머신 다이어그램]]) |
| 조합 · 시나리오 | 페어와이즈 | 모든 변수 쌍의 값 조합을 최소 1회 포함하도록 케이스 축소 |
| | 분류 트리 | 입력 도메인을 트리로 분류해 조합 선택 |
| | 유즈케이스 테스트 | 사용자 시나리오의 주·대안 흐름 검증 |

## III. 비교 및 동향

### 가. 블랙박스 vs 화이트박스

| 비교 항목 | 블랙박스 | [[화이트박스 테스트\|화이트박스]] |
| --- | --- | --- |
| 근거 | 요구사항 명세 | 소스 코드 구조 |
| 관점 | 외부 기능·사용자 | 내부 논리·개발자 |
| 대표 기법 | 동등 분할, 경계값, 결정 테이블 | 구문·결정·조건·MC/DC 커버리지 |
| 주 적용 레벨 | 통합·[[시스템 테스트\|시스템]]·[[인수 테스트\|인수]] (전 레벨 가능) | [[단위 테스트\|단위]]·통합 |
| 발견 결함 | 기능 누락·명세 불일치 | 미실행 코드·논리 오류 |

### 나. 동향

- 명세에서 LLM으로 동등 분할·경계값 케이스를 자동 생성
- API 명세(OpenAPI) 기반 계약 테스트로 마이크로서비스 경계를 조기 검증
