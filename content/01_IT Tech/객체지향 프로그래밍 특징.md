# 객체지향 프로그래밍 특징

---

## I. 추상화·캡슐화·상속·다형성, 객체지향 프로그래밍 특징의 개요

### 가. 정의

- 객체지향 프로그래밍(OOP)이 **변경에 강하고 재사용 가능한 구조를 만들기 위해 갖는 추상화·캡슐화·상속성·다형성의 4대 특징**

### 나. 필요성

| 구분 | 내용 |
| --- | --- |
| 복잡성 관리 | 본질만 추출한 모델로 도메인 이해도 향상 |
| 변경 국소화 | 내부 구현 변경이 외부로 퍼지지 않음 ([[결합도]] 감소) |
| 재사용 | 공통 속성·행위를 상위 클래스로 모아 중복 제거 |
| 확장성 | 인터페이스 중심 설계로 기존 코드 수정 없이 기능 추가 |

---

- 현실 세계를 추상화해 클래스를 정의하고, 상속으로 확장하며, 재정의로 다형성을, 내부 은닉으로 캡슐화를 구현한 객체들이 메시지로 협력

### 나. 4대 특징

| 구분 | 요소 | 설명 |
| --- | --- | --- |
| 모델링 | [[추상화]] (Abstraction) | 불필요한 세부를 제거하고 목적에 맞는 공통 속성·행위만 추출해 [[클래스]]로 정의 |
| 은닉 | [[캡슐화]] (Encapsulation) | 데이터와 메서드를 묶고 접근 제어자로 외부 직접 접근 차단 ([[정보은닉]]) |
| 재사용 | [[상속성]] (Inheritance) | 상위 클래스의 속성·메서드를 하위 클래스가 물려받아 재사용·확장 |
| 유연성 | [[다형성]] (Polymorphism) | 같은 메시지에 객체 타입별로 다르게 동작 (오버라이딩·오버로딩) |

## III. 비교 및 동향

### 가. 오버로딩 vs 오버라이딩

| 비교 항목 | 오버로딩 (Overloading) | 오버라이딩 (Overriding) |
| --- | --- | --- |
| 관계 | 같은 클래스 내 | 상속 관계의 상·하위 클래스 |
| 시그니처 | 이름 같고 매개변수 다름 | 이름·매개변수·반환형 동일 |
| 바인딩 | 컴파일 시점 (정적) | 실행 시점 (동적) |
| 다형성 유형 | 임시(Ad-hoc) 다형성 | 서브타입 다형성 |
| 목적 | 같은 의미 연산의 편의 제공 | 하위 클래스별 동작 변경 |

### 나. 동향

- 깊은 상속 계층의 취약성 때문에 상속보다 합성(Composition)과 인터페이스를 우선하는 설계 권장
- Java Record·Kotlin data class 등 불변 객체와 함수형 기능을 결합한 멀티 패러다임 확산
- [[DDD (Domain Driven Design)|DDD]] 도메인 모델 구현의 기반으로 캡슐화·[[응집도]] 원칙 활용
