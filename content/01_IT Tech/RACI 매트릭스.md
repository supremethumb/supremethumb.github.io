# RACI 매트릭스

---

## I. 누가 하고 누가 책임지는가, RACI 매트릭스의 개요

### 가. 정의

- 작업별 역할을 **R(Responsible)·A(Accountable)·C(Consulted)·I(Informed)** 로 지정하는 책임 할당 매트릭스(RAM, Responsibility Assignment Matrix)의 대표 형식 (PMBOK 자원관리 계획수립의 도구)

### 나. 필요성 및 특징

| 구분 | 내용 |
| --- | --- |
| 책임 명확화 | 책임 소재 불분명에 따른 의사결정 지연·업무 공백 방지 |
| 단일 책임 | 작업마다 최종 책임자(A)는 한 명 |
| 소통 경로 정의 | 자문(C, 양방향)과 통보(I, 단방향) 대상을 구분해 의사소통 과부하 방지 |
| 구조 | 행은 작업([[WBS]] 요소), 열은 역할·조직(OBS)으로 교차 매핑 |

---

## II. 구조와 작성 규칙

### 가. 구조 예

| 작업 \ 역할 | PM | 아키텍트 | 개발자 | 고객 |
| --- | --- | --- | --- | --- |
| 요구사항 정의 | A | C | C | R |
| 아키텍처 설계 | A | R | C | I |
| 핵심 로직 구현 | I | C | A/R | I |
| 인수 테스트 | A | I | C | R |

- WBS 작업과 역할의 교차점에 코드를 배정. 한 사람이 A와 R을 겸할 수 있음

### 나. 구성요소와 규칙

| 구분 | 요소 | 설명 |
| --- | --- | --- |
| 역할 | R (Responsible) | 작업을 실제 수행하는 실행 담당, 여러 명 가능 |
| | A (Accountable) | 결과를 승인하고 최종 책임을 지는 1인 |
| | C (Consulted) | 수행 전·중에 의견을 주는 자문 대상, 양방향 소통 |
| | I (Informed) | 진행·결과를 통보받는 대상, 단방향 소통 |
| 작성 규칙 | A는 작업당 1명 | 책임 분산·전가 방지 |
| | R은 작업당 1명 이상 | 수행자 없는 작업 방지 |
| | C·I 최소화 | 과도한 자문·통보로 인한 지연 방지 |
| 검증 | 열 단위 점검 | 한 역할에 A·R이 몰리면 과부하, 공백이면 역할 재검토 |
| 변형 | RASCI | Support(S, 지원) 역할 추가 |
| | RACI-VS 등 | Verifier(V, 검증), Signatory(S, 서명) 추가 |

---

## III. 비교 및 동향

### 가. RAM 표현 방식 비교

| 비교 항목 | RACI 매트릭스 | 계층형 조직도 (OBS) | 텍스트형 직무기술서 |
| --- | --- | --- | --- |
| 표현 | 작업×역할 행렬 | 조직 계층 구조 | 역할별 서술 |
| 장점 | 작업별 책임·소통 경로 한눈에 파악 | 보고 체계 명확 | 상세 책임·자격 기술 |
| 한계 | 작업이 많으면 표가 비대 | 작업별 책임 표현 불가 | 작업 간 관계 파악 어려움 |
| 용도 | 실행 단계 책임 배정 | 조직 구성 | 채용·역할 정의 |

### 나. 동향

- **AI 거버넌스 적용**: 데이터 수집, 모델 학습·배포, 위험 평가 단계별로 책임자를 지정하는 RACI가 [[AI 거버넌스]] 체계에 활용
- **애자일 조직**: 고정 RACI 대신 팀 자율 위임 수준을 정하는 위임 포커(Delegation Poker) 등 병행
- **도구 연계**: 협업 도구의 담당자·승인자 필드와 RACI를 연동
