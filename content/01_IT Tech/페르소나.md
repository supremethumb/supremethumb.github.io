# 페르소나 (Persona)

---

## I. 사용자를 대표하는 가상 인물, 페르소나의 개요

### 가. 정의

- 사용자 조사 데이터를 바탕으로 **핵심 사용자 집단의 목표·행동·불편을 대표하도록 만든 가상의 인물 모델**로, 제품 기획과 UX 설계의 의사결정 기준 (Alan Cooper, 1999)

### 나. 필요성 및 특징

| 구분 | 내용 |
| --- | --- |
| 자기 참조 오류 방지 | 개발자·기획자가 자신을 사용자로 착각하는 문제 차단 |
| 탄력적 사용자 방지 | 상황마다 편한 대로 바뀌는 '모든 사용자' 가정 배제 |
| 공감 · 소통 | 이해관계자가 같은 사용자 상을 공유 |
| 데이터 기반 | 인터뷰·관찰·로그 등 실제 조사 결과에 근거 |

---

## II. 도출 절차 및 구성요소

### 가. 도출 절차

```mermaid
flowchart LR
    R["사용자 조사<br/>(인터뷰 · 관찰 · 로그 · 설문)"] --> P["패턴 분석<br/>(어피니티 다이어그램)"]
    P --> PE["페르소나 정의<br/>(목표 · 행동 · 불편)"]
    PE --> S["시나리오 · 고객 여정 지도"]
    S --> D["기능 정의 · UI 설계"]
```

- 조사 데이터를 행동 변수 기준으로 묶어 패턴을 찾고, 대표 인물로 정의한 뒤 시나리오·여정 지도와 설계의 기준으로 활용

### 나. 구성요소

| 구분 | 요소 | 설명 |
| --- | --- | --- |
| 인물화 | 아이덴티티 | 이름·사진·직업·인용구로 실재감 부여 |
| | 인구 통계 | 연령·거주지·가족 구성 등 배경 |
| 핵심 | 목표 · 동기 | 제품으로 달성하려는 목적 |
| | 불편 요소 (Pain Point) | 현재 겪는 문제와 좌절 |
| | 행동 변수 | 사용 환경, 숙련도, 이용 빈도, 선호 채널 |
| 맥락 | 시나리오 | 목표 달성을 위해 제품과 상호작용하는 이야기 |
| 분석 기법 | 어피니티 다이어그램 | 조사 결과를 유사성으로 묶어 특징 도출 |
| 우선순위 | 주 · 보조 페르소나 | 설계 기준이 되는 주 페르소나와 보조 페르소나 구분 |

---

## III. 비교 및 동향

### 가. 페르소나 vs 시장 세분화

| 비교 항목 | 페르소나 | 시장 세분화 |
| --- | --- | --- |
| 목적 | 제품·UX 설계 기준 | 표적 시장 선정·마케팅 전략 |
| 초점 | 목표·행동·맥락 (왜, 어떻게) | 인구통계·구매력·시장 규모 (누구, 얼마나) |
| 결과물 | 구체적 가상 인물 | 속성을 공유하는 고객 집단 |
| 주 데이터 | 인터뷰·관찰 등 정성 데이터 | 설문·매출 등 정량 데이터 |

### 나. 동향

- LLM에 페르소나 역할을 부여해 인터뷰·사용성 검토를 모의하는 합성 사용자 활용 (실제 조사 대체가 아닌 보조)
- 고객 데이터 플랫폼(CDP)의 행동 데이터로 페르소나를 갱신하는 데이터 기반 페르소나
- LLM 프롬프트에 역할을 지정하는 페르소나 프롬프팅 ([[프롬프트 엔지니어링]])
