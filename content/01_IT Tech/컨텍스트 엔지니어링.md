# 컨텍스트 엔지니어링(Context Engineering)

---

## I. LLM의 인지 최적화, 컨텍스트 엔지니어링의 개요

### 가. 컨텍스트 엔지니어링(Context Engineering)의 정의
- 대규모 언어 모델([[초거대 언어 모델|LLM]])이 한정된 컨텍스트 윈도우(Context Window) 내에서 최적의 추론을 수행하도록 검색된 지식, 메모리, 외부 도구 출력을 선별·압축·구조화하여 주입하는 동적 정보 아키텍처 설계 기술이다.

### 나. 컨텍스트 엔지니어링의 주요 특징 및 필요성
| 구분 | 내용 |
| :--- | :--- |
| **주의력 예산(Attention Budget) 관리** | 토큰 증가에 따른 중간 망각(Lost in the Middle) 방지 및 연산 비용 최적화 |
| **정보 오염 및 충돌 방지** | 불필요한 노이즈로 인한 Context Poisoning 및 상충 데이터 간 Context Clash 차단 |
| **Agentic 워크플로우 지원** | 단기/장기 메모리와 모델 컨텍스트 프로토콜([[MCP]]) 기반 도구 실행 결과를 동적 통합 |
| **비용 및 지연시간 절감** | Context Caching 및 프롬프트 구조화를 통해 GPU 추론 레이턴시와 토큰 과금 최소화 |

---

## II. 컨텍스트 엔지니어링의 아키텍처 및 핵심 구성요소

### 가. 컨텍스트 엔지니어링의 아키텍처 및 동작 원리

```mermaid
flowchart LR
    User["사용자 요청<br/>(Query)"]
    
    subgraph CE_Pipeline["Context Engineering Pipeline"]
        direction TB
        Gather["1. Context Gathering<br/>(수집: RAG, History, Tools)"]
        Filter["2. Selection & Filtering<br/>(선별: 연관도 스코어링)"]
        Compress["3. Compression & Dedup<br/>(압축: 토큰 최적화/중복제거)"]
        Format["4. Structuring & Assembly<br/>(구조화: 페이로드 조립)"]
        
        Gather --> Filter --> Compress --> Format
    end
    
    LLM["LLM<br/>(제한된 Context Window)"]
    Memory[("Memory<br/>(단기/장기 기억)")]
    Tools["External Tools<br/>(MCP 기반 API/DB)"]
    
    User --> Gather
    Memory <--> Gather
    Tools <--> Gather
    Format =="최적화된 토큰 세트"==> LLM
    LLM --> Response["최종 응답 및 Action"]
```

* **동작 원리**: 사용자의 요청과 함께 외부 메모리 및 도구의 결과를 수집한 후, 컨텍스트 파이프라인을 통해 연관성 높은 정보만 필터링 및 압축하여 LLM의 컨텍스트 윈도우에 최적화된 형태로 전달함

### 나. 컨텍스트 엔지니어링의 핵심 기술 요소

| 구분 | 요소기술(키워드) | 세부 설명 |
| :--- | :--- | :--- |
| **정보 수집** | Context Selection | RAG(검색 증강 생성)를 활용하여 사용자 쿼리와 연관성이 높은 고품질 데이터 선별 |
| **정보 압축** | Context Compression | 문서 요약 및 필수 정보 추출을 통해 한정된 Context Window 내로 정보량 축소 |
| **정보 정제** | Deduplication / Resolution | 중복 데이터 제거 및 상충되는 정보 간의 충돌(Context Clash) 논리적 해결 |
| **기억 관리** | Memory Management | 대화 기록(단기 메모리) 및 사용자 프로필/선호도(장기 메모리)의 연속성 유지 |
| **도구 연동** | Tool Integration / [[MCP]] | 모델 컨텍스트 [[프로토콜]](MCP) 등을 통한 실시간 외부 API 연동 및 결과값 컨텍스트 주입 |
| **자원 할당** | Token Budgeting | LLM의 정보 처리 능력(Attention Budget)을 고려한 소스별/기능별 토큰 할당 최적화 |
| **구조화** | Prompt Structuring | 시스템 지시문, 사용자 쿼리, Few-shot 예제의 명확한 구분 및 마크다운 기반 템플릿 배치 |
| **성능 최적화** | Context Caching | 자주 참조되는 방대한 컨텍스트(시스템 매뉴얼, 코드베이스 등)를 캐싱하여 비용 및 지연 단축 |

## III. 컨텍스트 엔지니어링과 프롬프트 엔지니어링 비교 및 전망

### 가. 프롬프트 엔지니어링과의 비교

| 비교 항목 | [[프롬프트 엔지니어링|프롬프트 엔지니어링(Prompt Engineering)]] | 컨텍스트 엔지니어링(Context Engineering) |
| :--- | :--- | :--- |
| **핵심 목적** | 의도한 답변을 유도하기 위한 **최적의 지시어 설계** | AI가 작업을 수행하기 위한 **최적의 정보 환경 및 시스템 구축** |
| **최적화 대상** | 단어 선택, 문장 구조, 어조, 예제 텍스트 | 메모리, 데이터 파이프라인 검색(RAG), 도구 출력(API) |
| **데이터 속성** | 정적 텍스트 기반 (사전 정의된 규칙 위주) | 동적/실시간 데이터, 스트리밍, 멀티모달 정보의 통합 |
| **접근 방식** | 시행착오(Heuristic) 기반의 수동 튜닝 | 에이전트 플랫폼 기반 자동화 리트리버 및 토큰 예산 관리 |
| **적용 분야** | 단순 챗봇 질의응답, 일회성 텍스트 생성 | 자율형 AI 에이전트(Agentic AI), 엔터프라이즈 AI 시스템 |

### 나. 향후 기술 전망 및 동향

- **MCP(Model Context Protocol) 기반 표준 인터페이스 확산**: 앤트로픽 주도의 오픈 표준 MCP가 안착되면서 파일시스템, DB, SaaS API 등 이기종 데이터 소스가 표준화된 컨텍스트 파이프라인으로 직결됨.
- **KV Cache 기반 Context Caching 보편화**: 대용량 시스템 프롬프트, 도메인 온톨로지, 방대한 소스코드를 GPU 메모리 수준에서 영구/반영구 캐싱하여 API 호출 비용 70% 이상 절감 및 즉각적 추론 응답 실현.
- **자율형 에이전트의 동적 컴팩션(Compaction) 필수화**: 수십 턴에 걸친 에이전트 도구 호출 과정에서 불필요한 중간 페이로드를 실시간으로 요약·가비지 컬렉션하는 지능형 토큰 압축 레이어가 정착됨.
