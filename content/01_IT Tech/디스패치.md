# 디스패치 (Dispatch)

---

## I. 선택된 프로세스에 CPU를 넘기는, 디스패치의 개요

### 가. 정의

- 단기 [[스케줄링|스케줄러]]가 고른 [[프로세스]]·스레드에 **실제로 [[CPU]] 제어권을 넘겨 준비(Ready) → 실행(Running) 상태로 전환**하는 동작, 이를 수행하는 커널 모듈이 디스패처

### 나. 특징

| 구분 | 내용 |
| --- | --- |
| 역할 분리 | 스케줄러는 "누구를" 결정, 디스패처는 "전환"을 실행 |
| 문맥 교환 수반 | 이전 프로세스 상태 저장, 새 프로세스 상태 복원 ([[문맥 교환]]) |
| 디스패치 지연 | 한 프로세스를 멈추고 다른 프로세스를 시작하기까지의 시간, 실시간 OS의 핵심 지표 |

---

## II. 동작 구조 및 구성요소

### 가. 디스패치 동작 개념도

```mermaid
flowchart LR
    T["타이머 인터럽트<br/>또는 I/O 대기"] --> S["단기 스케줄러<br/>다음 프로세스 선택"]
    S --> D["디스패처"]
    D --> SV["P0 문맥을 PCB0에 저장"]
    SV --> RS["P1 문맥을 PCB1에서 복원"]
    RS --> M["사용자 모드 전환"]
    M --> J["P1의 PC로 분기, 실행 재개"]
```

- 스케줄러가 P1을 고르면 디스패처가 문맥 교환 → 사용자 모드 전환 → 저장된 PC로 분기 순으로 수행

### 나. 구성요소

| 구분 | 요소 | 설명 |
| --- | --- | --- |
| 기능 | 문맥 교환 | 레지스터·PC 등 CPU 상태를 [[PCB(Process Control Block)\|PCB]]에 저장·복원 |
| | 모드 전환 | 커널 모드에서 사용자 모드로 복귀 |
| | 분기 | 새 프로세스가 중단됐던 위치(PC)부터 실행 재개 |
| 자료 구조 | PCB / TCB | 프로세스·스레드 단위 문맥 저장 영역 |
| | 준비 큐 (Ready Queue) | 스케줄러가 다음 실행 대상을 고르는 대기열 |
| 계기 | 타이머 [[인터럽트]] | 선점형 스케줄링에서 시간 할당량 만료 시 디스패치 유발 |
| | 블로킹·종료 | 실행 중 프로세스가 I/O 대기나 종료로 CPU를 내놓을 때 |
| 성능 지표 | 디스패치 지연 | 짧을수록 응답성 우수 |

---

## III. 비교 및 동향

### 가. 스케줄러 vs 디스패처

| 비교 항목 | 단기 스케줄러 | 디스패처 |
| --- | --- | --- |
| 역할 | 다음 실행 프로세스 결정 (정책) | 결정된 프로세스로 전환 (메커니즘) |
| 주요 기능 | 우선순위 계산, RR·SJF 등 정책 적용 | 문맥 저장·복원, 모드 전환, 분기 |
| 호출 시점 | 프로세스 생성·대기·종료, 시간 할당량 만료 | 스케줄러 결정 직후 |
| 소요 시간 | 알고리즘 복잡도에 따라 변동 | 아키텍처 의존, 비교적 일정 |

### 나. 동향

- **사용자 수준 스케줄링**: Go 고루틴, Java 가상 스레드처럼 런타임이 사용자 공간에서 전환해 커널 진입 없이 디스패치 비용 축소
- **선점형 커널**: Linux PREEMPT_RT가 6.12에서 메인라인에 병합, 커널 실행 중에도 선점해 실시간 OS급 디스패치 지연 확보
- **[[가상화]]**: [[Hypervisor (VMM)|하이퍼바이저]]가 vCPU를 물리 CPU에 디스패치하는 2단계 스케줄링 구조
