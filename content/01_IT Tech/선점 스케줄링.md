# 선점 스케줄링 (Preemptive Scheduling)

---

## I. 응답성을 위한 강제 회수, 선점 스케줄링의 개요

### 가. 정의

- [[OS(운영체제)|운영체제]]가 실행 중인 프로세스의 **[[CPU]]를 강제로 회수해 우선순위가 높거나 차례가 된 프로세스에 할당**하는 [[스케줄링]] 방식

### 나. 특징

| 구분 | 내용 |
| --- | --- |
| 응답성 | 긴급·대화형 작업을 빠르게 처리 |
| 공정성 | 시간 할당량으로 한 프로세스의 CPU 독점 방지 |
| 오버헤드 | 잦은 [[문맥 교환]] 비용 |
| 동기화 부담 | 실행 도중 중단되므로 공유 자원 보호(락, [[세마포어]]) 필요 |

---

## II. 동작 구조 및 구성요소

### 가. 선점 동작 개념도

```mermaid
flowchart LR
    A["Process A 실행"] -->|"타이머 만료 또는<br/>고우선순위 도착"| INT["인터럽트"]
    INT --> SCH["스케줄러"]
    SCH --> SV["A 문맥을 PCB A에 저장"]
    SV --> LD["B 문맥을 PCB B에서 복원"]
    LD --> B["Process B 실행"]
```

- 타이머 [[인터럽트]]나 우선순위 높은 작업 도착 시 스케줄러가 개입해 실행 중인 프로세스를 준비 큐로 되돌리고 다른 프로세스를 디스패치

### 나. 알고리즘 및 구성요소

| 구분 | 요소 | 설명 |
| --- | --- | --- |
| 알고리즘 | RR (Round Robin) | 동일한 시간 할당량(Time Quantum) 후 교대, 할당량이 너무 크면 FCFS와 같아지고 너무 작으면 문맥 교환 과다 |
| | SRT (Shortest Remaining Time) | 남은 실행시간이 가장 짧은 작업이 선점 (SJF의 선점형) |
| | 선점형 우선순위 | 더 높은 우선순위 작업이 도착하면 즉시 선점 |
| | MLQ (Multi-Level Queue) | 작업 유형별로 큐를 나누고 큐마다 다른 알고리즘·우선순위 적용, 큐 간 이동 없음 |
| | MLFQ (Multi-Level Feedback Queue) | 큐 간 이동 허용, CPU를 오래 쓰면 하위 큐로 내려가며 하위 큐일수록 할당량 증가 |
| 메커니즘 | 타이머 인터럽트 | 시간 할당량 만료를 알리는 하드웨어 신호 |
| | [[PCB(Process Control Block)\|PCB]] | 중단된 프로세스의 문맥 저장 |
| 기아 방지 | 에이징 (Aging) | 오래 기다린 작업의 우선순위 상향, [[기아\|기아(Starvation)]] 방지 |

---

## III. 비교 및 동향

### 가. 선점형 vs 비선점형

| 비교 항목 | 선점형 | [[비선점방식 유형\|비선점형]] |
| --- | --- | --- |
| CPU 반환 | OS가 강제 회수 | 프로세스가 자발적으로 반환 |
| 응답시간 | 빠르지만 예측 어려움 | 느리지만 예측 쉬움 |
| 문맥 교환 | 많음 | 적음 |
| 동기화 | 공유 자원 보호 부담 큼 | 상대적으로 단순 |
| 적합 환경 | 시분할, 대화형, 실시간 | 일괄 처리 |
| 대표 알고리즘 | RR, SRT, MLQ, MLFQ | FCFS, SJF, HRN |

### 나. 동향

- **Linux 스케줄러**: 2.6.23부터 쓰인 CFS(vruntime + 레드블랙 트리)를 6.6에서 EEVDF로 교체, 지연 민감 작업 반영
- **PREEMPT_RT 메인라인화**: Linux 6.12에서 실시간 선점 패치가 메인라인에 병합, 커널 코드 실행 중에도 선점 가능
- **에너지 인지 스케줄링 (EAS)**: ARM big.LITTLE 등 이기종 코어에서 전력 모델로 코어를 선택해 성능과 배터리 효율 조정
