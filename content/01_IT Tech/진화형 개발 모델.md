# 진화형 개발 모델 (Evolutionary Model)

---

## I. 불명확한 요구를 키워 가는 개발, 진화형 개발 모델의 개요

### 가. 정의

- 요구사항이 불명확할 때 **핵심 기능부터 개발해 인도하고, 사용자 피드백으로 요구를 정제하며 버전마다 시스템을 확장·개선**하는 [[SDLC]] 모델

### 나. 특징

| 구분 | 내용 |
| --- | --- |
| 등장 배경 | [[워터폴\|폭포수]]의 경직성, 요구사항 [[변동성]] 증가 |
| 반복 · 점증 병행 | 기능 추가(점증)와 완성도 향상(반복)을 함께 수행 |
| 피드백 중심 | 버전마다 사용자 평가로 다음 요구 확정 |
| 조기 가치 | 동작하는 버전을 일찍 제공해 Time-to-Market 단축 |

---

## II. 수행 절차 및 구성요소

### 가. 수행 절차

```mermaid
flowchart LR
    INIT["핵심 요구사항 정의"] --> DEV["설계 · 구현"]
    DEV --> TEST["테스트 · 통합"]
    TEST --> REL["버전 릴리스 (V1, V2 ...)"]
    REL --> FB{"사용자 평가"}
    FB -- "요구 변경 · 추가" --> DEV
    FB -- "목표 달성" --> FIN["최종 시스템"]
```

- 한 번에 전체를 만들지 않고, 릴리스와 피드백을 반복하며 기능과 품질을 고도화

### 나. 구성요소

| 구분 | 요소 | 설명 |
| --- | --- | --- |
| 접근법 | [[반복적 개발 모델\|반복 (Iterative)]] | 골격을 먼저 만들고 반복으로 완성도 향상 |
| | [[증분형 개발 모델\|점증 (Incremental)]] | 기능 단위로 하나씩 추가 |
| 요구 관리 | 제품 백로그 | 기능·결함·비기능 요구를 우선순위로 관리 |
| 위험 관리 | [[프로토타이핑 모델\|프로토타이핑]] | UI·핵심 알고리즘을 시제품으로 조기 검증 |
| 일정 관리 | 타임박싱 | 반복 주기를 1~4주로 고정 |
| 자동화 | CI/CD | 잦은 릴리스의 빌드·테스트·배포 부담 감소 |
| 사업 검증 | [[01_IT Tech/MVP\|MVP]] | [[린 방법론\|Lean]] Startup의 최소 기능 제품으로 가설 검증 |

---

## III. 비교 및 동향

### 가. 진화형 vs 폭포수

| 비교 항목 | 진화형 | [[워터폴\|폭포수]] |
| --- | --- | --- |
| 요구 변경 | 변경을 전제로 수용 | 초기 확정 후 동결 |
| 인도 시점 | 버전별 다회 | 최종 단계 1회 |
| 리스크 | 피드백으로 조기 식별 | 후반 테스트 단계에 집중 |
| 적합 프로젝트 | 요구 변동이 큰 신규 서비스 | 요구가 명확·안정적인 시스템 |
| 약점 | 범위 통제 곤란, 구조 퇴화 위험 | 변경 비용 큼 |

### 나. 동향

- [[SCRUM|Scrum]]·Kanban 등 [[Agile]] 방법론이 진화형 모델의 반복·피드백 원칙을 실무 프랙티스로 정착
- [[DevOps]]와 [[클라우드 네이티브]] 인프라([[컨테이너]], [[쿠버네티스]])로 버전 주기가 상시 배포 수준으로 단축
