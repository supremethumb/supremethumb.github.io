# 비대칭키 암호화 (Asymmetric-key Cryptography)

---

## I. 키 분배 문제의 해법, 비대칭키 암호화의 개요

### 가. 정의

- **공개키와 개인키 한 쌍을 사용하여, 한 키로 암호화한 것은 다른 키로만 복호화**되도록 하는 암호 방식으로 키 교환·전자서명·부인방지 제공

### 나. 특징

| 구분 | 내용 |
| --- | --- |
| 키 분배 해결 | 공개키는 공개, 개인키만 비밀 보관 (n명에 2n개 키) |
| 수학적 난제 | 소인수분해([[RSA (Rivest Shamir Adleman)\|RSA]]), 이산대수([[Elgamel\|ElGamal]], [[DSA]]), 타원곡선 이산대수([[ECC]]) |
| 두 가지 용도 | 수신자 공개키로 암호화(기밀성), 송신자 개인키로 서명(인증·부인방지) |
| 성능 | 대칭키보다 느려 세션키 교환·서명에 주로 사용 |

---

## II. 동작 구조 및 구성요소

### 가. 암호화 모드와 서명 모드

```mermaid
flowchart TB
    subgraph M1["암호화 (기밀성)"]
        direction LR
        S1["송신자 평문"] -->|"수신자 공개키"| C1["암호문"]
        C1 -->|"수신자 개인키"| R1["수신자 평문"]
    end
    subgraph M2["전자서명 (인증 · 부인방지)"]
        direction LR
        S2["메시지 해시"] -->|"송신자 개인키"| G["서명"]
        G -->|"송신자 공개키"| V["검증"]
    end
```

- 기밀성은 수신자 공개키로 암호화하고, 인증·부인방지는 송신자 개인키로 서명하여 공개키로 검증

### 나. 구성요소

| 구분 | 요소 | 설명 |
| --- | --- | --- |
| 알고리즘 | RSA | 큰 두 소수 곱의 소인수분해 난제 기반, 암호화·서명 모두 가능 |
| | ECC | 타원곡선 이산대수 기반, 256비트 키가 RSA 3072비트와 비슷한 강도 |
| | DSA / KCDSA | 이산대수 기반 전자서명 전용 (미국 / 국내 표준) |
| | [[디피-헬만 알고리즘\|Diffie-Hellman]] | 이산대수 기반 키 합의 |
| 키 | 공개키 | 암호화, 서명 검증에 사용 |
| | 개인키 | 복호화, 서명 생성에 사용 |
| 인프라 | PKI | 인증기관(CA)이 X.509 인증서로 공개키와 소유자를 결합·보증 |

---

## III. 비교 및 동향

### 가. 비대칭키 vs 대칭키

| 비교 항목 | 비대칭키 | [[대칭키 암호화\|대칭키]] |
| --- | --- | --- |
| 키 | 공개키·개인키 쌍 | 동일 비밀키 |
| 키 수 (n명) | $2n$ | $\frac{n(n-1)}{2}$ |
| 속도 | 느림 | 빠름 |
| 키 분배 | 공개키 배포로 해결 | 별도 안전 채널 필요 |
| 대표 알고리즘 | RSA, ECC, ElGamal | [[AES]], ARIA, SEED |
| 활용 | 키 교환, 전자서명, 인증서 | 대용량 데이터 암호화 |

### 나. 동향

- **하이브리드 암호**: 공개키로 세션키를 교환하고 데이터는 대칭키로 암호화 (TLS, [[전자봉투]])
- **[[양자내성암호]] 전환**: NIST가 2024년 FIPS 203(ML-KEM), 204(ML-DSA), 205(SLH-DSA)를 확정, RSA·ECC 대체 추진
- **암호 민첩성**: 알고리즘 교체를 쉽게 하는 Crypto Agility 설계와 하이브리드 키 교환(X25519+ML-KEM) 확산
