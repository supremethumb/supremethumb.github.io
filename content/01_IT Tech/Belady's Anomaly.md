# Belady's Anomaly (벨라디의 모순)

---

## I. 프레임을 늘렸는데 부재가 늘어나는, Belady's Anomaly의 개요

### 가. 정의

- 프로세스에 할당한 **페이지 프레임 수를 늘렸는데도 페이지 부재(Page Fault) 횟수가 오히려 증가**하는 현상 (Belady·Nelson·Shedler, 1969)

### 나. 특징

| 구분 | 내용 |
| --- | --- |
| 발생 알고리즘 | [[FIFO]] 페이지 교체가 대표적, Second Chance(Clock)·Random 교체도 발생 가능 |
| 원인 | 포함 성질(Inclusion Property)을 만족하지 않는 교체 알고리즘 |
| 미발생 알고리즘 | [[LRU]], [[OPT]], LFU 등 스택 알고리즘 |
| 의미 | 메모리를 늘리면 성능이 좋아진다는 직관이 FIFO에서는 성립하지 않음 |

---

## II. 발생 원리 및 구성요소

### 가. 발생 예시 (FIFO)

```mermaid
flowchart LR
    REF["참조열<br/>1 2 3 4 1 2 5 1 2 3 4 5"] --> F3["프레임 3개<br/>페이지 부재 9회"]
    REF --> F4["프레임 4개<br/>페이지 부재 10회"]
    F3 -.->|"프레임 증가에도<br/>부재 증가"| F4
```

- 프레임 4개일 때는 적재 순서가 달라져 곧 다시 쓸 페이지(1, 2)가 먼저 쫓겨나 부재가 1회 늘어남

### 나. 구성요소

| 구분 | 요소 | 설명 |
| --- | --- | --- |
| 원인 | FIFO 교체 | 적재 시각만 보고 교체, 사용 빈도·최근성 무시 |
| | 포함 성질 결여 | n개 프레임에 있는 페이지 집합이 n+1개 프레임의 집합에 포함되지 않음 |
| 해결 조건 | 스택 알고리즘 | 모든 시점에 M(n) ⊆ M(n+1)을 만족해 프레임 증가 시 부재가 늘지 않음 |
| 스택 알고리즘 | [[LRU]] | 가장 오래 참조되지 않은 페이지 교체 |
| | [[OPT]] | 앞으로 가장 오래 쓰이지 않을 페이지 교체, 이론적 최적 |
| | [[LFU]] | 참조 횟수가 가장 적은 페이지 교체 |

---

## III. 비교 및 동향

### 가. FIFO vs LRU

| 비교 항목 | FIFO | LRU |
| --- | --- | --- |
| 교체 기준 | 적재된 지 가장 오래된 페이지 | 참조된 지 가장 오래된 페이지 |
| 자료구조 | 큐 | 스택·연결 리스트, 카운터 |
| 포함 성질 | 불만족 | 만족 |
| Belady's Anomaly | 발생 가능 | 발생하지 않음 |
| 구현 비용 | 낮음 | 높음 (참조마다 갱신) |

### 나. 동향

- **근사 LRU**: 실제 OS는 참조 비트 기반 Clock·[[NUR]] 계열로 LRU를 근사, 이들은 스택 알고리즘이 아니므로 이론상 모순이 생길 수 있으나 실무 영향은 작음
- **Linux MGLRU**: 6.1부터 여러 세대(Generation)로 페이지를 나눠 최근성을 더 정밀하게 근사
- **캐시 정책 연구**: 웹·CDN 캐시에서 FIFO 기반 S3-FIFO 등이 LRU보다 높은 적중률을 보인 연구 결과 등장 (단순 FIFO의 재평가)
