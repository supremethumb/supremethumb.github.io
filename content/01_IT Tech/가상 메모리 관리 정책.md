# 가상 메모리 관리 정책

---

## I. 가상메모리 성능 최적화를 위한 관리 기법의 개요
### 가. 가상기억장치 관리정책의 정의
- 물리적 메모리 한계를 극복하고 다중 프로그래밍 효율을 높이기 위해, 프로세스에 메모리를 할당하고, 필요한 데이터를 인출하여, 적절한 위치에 배치하고, 부족 시 교체하는 일련의 최적화 정책.
- 부적절한 관리 정책 적용 시 [[스레싱]](Thrashing) 발생으로 시스템 성능이 급격히 저하되므로 최적의 [[알고리즘]] 적용이 필수적임.
### 나. 핵심 키워드
- 할.배.인.교, Paging/Segmentation, Demand/Pre-fetch, First/Best/Worst Fit, [[LRU]]/[[LFU]], Thrashing, Working Set.

### 나. 4대 관리정책 상세 내용 및 주요 기법

| 정책 (Policy)                | 개념 (Concept)                                    | 주요 기법 및 알고리즘                                                                                                     |
| -------------------------- | ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 1. 할당<br>(Allocation)  | [[프로세스]] 실행을 위해 주기억장치<br>양(Quantity)을 얼마나 줄 것인가 | - 고정 할당: 균등 할당, 비례 할당<br>- 가변 할당: 프로세스 특성/상황 고려 동적 할당                                                    |
| 2. 배치<br>(Placement)   | 적재할 데이터를 주기억장치의<br>어느 위치(Where)에 둘 것인가      | - First-fit (최초): 첫 번째 빈 공간<br>- Best-fit (최적): [[단편화]] 가장 작은 공간<br>- Worst-fit (최악): 가장 큰 공간 (남은 공간 활용) |
| 3. 인출<br>(Fetch)       | 보조기억장치에서 데이터를<br>언제(When) 가져올 것인가           | - Demand Fetch (요구): Page Fault 시 인출<br>- Pre-fetch (예상): 참조 예상 데이터 미리 인출                                |
| 4. 교체<br>(Replacement) | 메모리가 꽉 찼을 때<br>누구(Who)를 내보낼 것인가             | - [[FIFO]], [[OPT]](최적/비현실적)<br>- LRU(최근최소), LFU(빈도), [[NUR]], SCR                                   |

## III. 관리정책 부재 시 문제점 및 해결 방안
### 가. 스레싱(Thrashing) 발생 및 성능 저하
- 현상: 과도한 페이지 교체로 인해 [[CPU]]가 프로세스 실행보다 페이지 교체(Swap In/Out)에 시간을 더 소모하여 시스템 처리율이 급격히 떨어지는 현상.
- 원인: 부적절한 교체 정책 사용, 다중 프로그래밍 정도가 너무 높을 때 발생.
### 나. 해결 방안 (Locality 활용)
- Working Set Model: 프로세스가 일정 시간 동안 자주 참조하는 페이지 집합을 메모리에 상주시켜 Page Fault를 줄임.
- PFF (Page Fault Frequency): 페이지 부재율의 상한/하한을 두어 메모리 할당량을 동적으로 조절함.
