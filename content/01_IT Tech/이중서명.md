# 이중서명 (Dual Signature)

---

## I. 주문과 결제를 나눠 보이는, 이중서명의 개요

### 가. 정의

- SET(Secure Electronic Transaction) 프로토콜에서 **주문 정보(OI)와 결제 정보(PI)의 해시를 연결해 하나의 서명으로 묶어, 상점과 은행이 각자 필요한 정보만 보면서 두 정보의 연관성을 검증**하게 하는 서명 기법

### 나. 특징

| 구분 | 내용 |
| --- | --- |
| 정보 분리 | 상점은 결제 정보를, 은행(PG)은 주문 내역을 보지 못함 |
| 연계 증명 | 특정 주문과 특정 결제가 한 거래임을 증명 |
| 부인방지 | 구매자 개인키로 서명 |
| 무결성 | OI·PI 어느 쪽이 바뀌어도 검증 실패 |
| 배경 | 1996년 Visa·MasterCard가 제정한 SET의 핵심 기술 |

- 생성: $DS = Sign_{KR_c}(H(H(PI) \parallel H(OI)))$
- 상점은 OI와 PIMD를 받아 $H(OI)$를 계산해 PIMD와 연결한 해시를 서명과 대조하고, 은행은 PI와 OIMD로 같은 방식으로 검증

### 나. 구성요소

| 구분 | 요소 | 설명 |
| --- | --- | --- |
| 원천 정보 | OI (주문 정보) | 품목·수량 등 상점이 필요한 정보 |
| | PI (결제 정보) | 카드번호 등 은행이 필요한 정보 |
| 해시 | OIMD / PIMD | OI·PI 각각의 메시지 다이제스트 |
| | POMD | $H(PIMD \parallel OIMD)$, 서명 대상 |
| 서명 | 구매자 개인키 | POMD에 서명해 이중서명 생성 |
| | 구매자 공개키 | 상점·은행이 인증서로 서명 검증 |
| 전달 | 상점에 보내는 것 | OI, PIMD, DS |
| | 은행에 보내는 것 | PI, OIMD, DS (전자봉투로 암호화) |

## III. 비교 및 동향

### 가. 이중서명 vs 은닉서명

| 비교 항목 | 이중서명 | 은닉서명 (Blind Signature) |
| --- | --- | --- |
| 목적 | 다자 거래의 정보 분리와 연계 증명 | 서명자에게 내용을 숨긴 채 서명 획득 |
| 핵심 속성 | 정보 분리, 상호 연계 무결성 | 익명성, 연결 불가능성 |
| 서명 주체 | 구매자 | 서명자(발급기관) |
| 적용 | SET 전자결제 | 전자투표, 전자화폐 |

### 나. 동향

- **SET 퇴장**: 클라이언트 인증서 배포 부담으로 확산 실패, 이후 TLS 기반 결제로 대체
- **3-D Secure 2와 토큰화**: EMV 3DS 위험 기반 인증과 카드번호 토큰화로 상점의 카드정보 비노출 실현
- **프라이버시 결제 연구**: [[영지식증명]]·MPC로 결제 유효성만 증명하는 방식 연구
