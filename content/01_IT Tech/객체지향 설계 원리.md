# 객체지향 설계 원리 (SOLID)

---

## I. 변경에 유연한 설계 지침, 객체지향 설계 원리의 개요

### 가. 정의

- 로버트 마틴(Robert C. Martin)이 정리한 5가지 [[객체지향]] 설계 원칙(SOLID)으로, **높은 [[응집도]]와 낮은 [[결합도]]** 를 달성하여 재사용성·[[유지보수]]성·확장성을 높이는 설계 가이드라인

### 나. 필요성

| 구분 | 내용 |
| --- | --- |
| 복잡성 제어 | SW 규모 증가에 따른 구조적 복잡성 관리 |
| 변경 용이성 | 요구 변경 시 수정 범위를 최소화하고 부작용(Side Effect) 방지 |
| 재사용성 | 독립적인 모듈 단위의 재사용 촉진 |

### 나. 원칙별 내용

| 원칙 | 의미 | 설계 효과 |
| --- | --- | --- |
| **SRP** (Single Responsibility)<br>단일 책임 원칙 | [[클래스]]가 변경되어야 하는 이유는 하나뿐이어야 함 | 응집도 향상, 한 책임의 변경이 다른 책임에 미치는 영향 차단 |
| **OCP** (Open-Closed)<br>개방-폐쇄 원칙 | 확장에는 열려 있고, 수정에는 닫혀 있어야 함 | 인터페이스·[[다형성]]으로 기존 코드 변경 없이 기능 추가 |
| **LSP** (Liskov Substitution)<br>리스코프 치환 원칙 | 하위 타입은 언제나 상위 타입을 대체할 수 있어야 함 | 상속 규약(사전·사후 조건) 준수로 다형성의 안전성 보장 |
| **ISP** (Interface Segregation)<br>인터페이스 분리 원칙 | 클라이언트는 사용하지 않는 메서드에 의존하지 않아야 함 | 범용 인터페이스 대신 작고 구체적인 인터페이스로 불필요한 의존 제거 |
| **DIP** (Dependency Inversion)<br>의존성 역전 원칙 | 고수준·저수준 모듈 모두 [[추상화]]에 의존해야 함 | 결합도 감소, 의존성 주입(DI)의 기반 |

## III. OOP 특징과의 관계 및 활용 동향

### 가. OOP 특징과 SOLID의 관계

| 구분 | OOP 특징 (캡·추·다·정·상) | 설계 원칙 (SOLID) |
| --- | --- | --- |
| 성격 | 언어가 제공하는 기술적 특성 (도구) | 특성을 올바르게 쓰기 위한 지침 (방법) |
| 예 | [[캡슐화]], [[추상화]], [[다형성]], [[정보은닉]], [[상속성]] | SRP, OCP, LSP, ISP, DIP |

### 나. 활용

- **Spring Framework**: DIP를 IoC/DI 컨테이너로 구현하여 객체 간 결합도 감소
- **[[디자인 패턴\|Design Pattern]]**: SOLID를 구체화한 검증된 설계 해법 (예: Strategy → OCP)
- **아키텍처 확장**: SRP는 [[DDD (Domain Driven Design)\|DDD]] Bounded Context 분리 기준, 헥사고날 아키텍처의 Port & Adapter는 DIP·OCP의 아키텍처 수준 적용 ([[Clean Architecture]])
- **AI 생성 코드 검증**: LLM 코드 생성 확산에 따라 정적 분석·코드 리뷰에서 SOLID 위반 여부를 품질 기준으로 활용
- **함수형 융합**: ISP·DIP는 함수 타입과 고차 함수 시그니처 설계 규약으로 계승
