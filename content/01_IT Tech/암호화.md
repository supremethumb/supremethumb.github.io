# 암호화 (Encryption)

---

## I. 기밀성·무결성 보장의 핵심 기반, 암호화의 개요

### 가. 암호화의 정의

- 인가되지 않은 제3자의 도청·위변조를 막기 위해 **알고리즘과 키(Key)로 평문(Plaintext)을 해독 불가능한 암호문(Ciphertext)으로 변환**하는 보안 기술
- [[기밀성]], [[무결성]], 인증(Authentication), 부인방지(Non-repudiation)를 제공

### 나. 설계 원리

| 원리 | 내용 |
| --- | --- |
| 커크호프의 원리 | 알고리즘은 공개되어도 키만 비밀이면 안전해야 함 |
| 혼돈 (Confusion) | 키와 암호문의 관계를 복잡하게 하여 키 추정을 어렵게 함 ([[Shannon의 암호 설계 원칙]]) |
| 확산 (Diffusion) | 평문 1비트 변화가 암호문 전체에 퍼지게 하여 통계적 특성 은닉 |
| 기본 연산 | 대치(Substitution), 전치(Transposition), 블록화, 확장·압축 |

---

## II. 암호화의 구조 및 핵심 기술

### 가. 암호화 처리 구조 및 분류 체계

```mermaid
flowchart TB
    subgraph PROCESS["암호화 및 복호화 처리"]
        direction LR
        P1["평문 M"] --> ENC["암호화 E"]
        K1["암호화 키 K1"] --> ENC
        ENC --> C["암호문 C = E_K1(M)"]
        C --> DEC["복호화 D"]
        K2["복호화 키 K2"] --> DEC
        DEC --> P2["평문 M = D_K2(C)"]
    end
    subgraph TAXONOMY["현대 암호 분류"]
        direction TB
        subgraph SYM["대칭키 (K1 = K2)"]
            BLOCK["블록 암호<br/>AES, ARIA, SEED"]
            STREAM["스트림 암호<br/>ChaCha20"]
        end
        subgraph ASYM["공개키 (K1 ≠ K2)"]
            CLASSIC["RSA, ECC"]
            PQC["양자내성암호<br/>ML-KEM, ML-DSA"]
        end
        subgraph PETS["프라이버시 보존 암호"]
            FHE["동형암호"]
            ZKP["영지식 증명"]
            FPE["형태보존 암호"]
        end
    end
    PROCESS ==> TAXONOMY
```

- 현대 암호 통신은 **공개키로 세션키를 교환하고 대칭키로 데이터를 암호화하는 하이브리드 구조**가 기본 ([[전자봉투]])
- 보호 범위가 저장·전송 중 데이터에서 **사용 중 데이터(Data-in-Use)** 와 **양자 위협 대응(PQC)** 으로 확장

### 나. 핵심 기술 요소

| 구분 | 기술 | 설명 |
| --- | --- | --- |
| 대칭키 (블록) | [[AES]], ARIA, SEED | SPN(AES·ARIA)·Feistel(SEED) 구조의 128bit 블록 암호, 저장 데이터 암호화 표준 ([[블록 암호화]]) |
| 대칭키 (스트림) | ChaCha20-Poly1305 | 키스트림과 평문 XOR, 모바일·TLS 1.3 고속 암호화 |
| 운용 모드 | GCM | CTR 모드 병렬 암호화 + 인증 태그를 동시 제공하는 AEAD |
| 공개키 (인수분해) | [[RSA (Rivest Shamir Adleman)\|RSA]] | 큰 수의 소인수분해 난제 기반, 2048bit 이상, 키 교환·서명 |
| 공개키 (이산대수) | [[ECC]] (ECDH, ECDSA) | 타원곡선 이산대수 난제, RSA보다 짧은 키(256bit)로 동등 보안 ([[타원곡선 암호]]) |
| 일방향 | [[해시함수]] (SHA-256, SHA-3), [[HMAC]] | 무결성 검증, 비밀번호 저장, 서명용 요약 |
| 형태보존 | FPE (FF1, FF3-1) | 길이·형식을 유지해 DB [[스키마]] 변경 없이 개인정보 암호화 |
| 연산보존 | [[동형 암호]] (CKKS, BFV) | 복호화 없이 암호문 상태로 연산, 민감 데이터 분석·AI 추론 보호 |
| 증명 | [[영지식증명\|영지식 증명]] (zk-SNARKs) | 비밀을 노출하지 않고 진위만 증명, DID 등에 활용 |
| 양자내성 | [[양자내성암호\|PQC]] (FIPS 203/204) | 격자 기반 ML-KEM(키 캡슐화)·ML-DSA(서명), 2024년 NIST 표준 확정 |

## III. 기술 비교 및 데이터 전주기 보호 전략

### 가. 대칭키 vs 공개키 vs 차세대 암호

| 비교 항목 | [[대칭키 암호화\|대칭키]] | [[비대칭키 암호화\|공개키]] | 동형암호 | PQC |
| --- | --- | --- | --- | --- |
| 키 관계 | 암호키 = 복호키 | 공개키 ≠ 개인키 | 연산키(Evaluation Key) 별도 | 공개키 ≠ 비밀키 |
| 필요 키 수 (N명) | N(N−1)/2 | 2N | - | 2N |
| 보안 기반 | 치환·전치 라운드 | 소인수분해·이산대수 | LWE/RLWE 격자 난제 | 격자·해시·코드 난제 |
| 속도 | 매우 빠름 | 느림 | 매우 느림 (가속기 필요) | 중간 |
| 주요 용도 | 저장·전송 데이터 암호화 | 키 교환, 전자서명, PKI | 사용 중 데이터 보호 | 양자 시대 키 교환·인증 |
| 알고리즘 | [[DES]], AES, SEED, ARIA | RSA, ECC, ElGamal | CKKS, BFV | ML-KEM, ML-DSA |

### 나. 데이터 상태별 전주기 보호

| 상태 | 보호 방법 |
| --- | --- |
| Data-at-Rest (저장) | AES-256-GCM, TDE·FDE, 주민번호·계좌번호 FPE |
| Data-in-Transit (전송) | TLS 1.3([[ECDHE]] + AES-GCM/ChaCha20), [[IP Sec\|IPsec]] [[VPN]], SSH |
| Data-in-Use (사용) | 동형암호, [[기밀컴퓨팅]](TEE: SGX/SEV) |

### 다. 키 관리 및 발전 방향

- **키 관리**: 암호 시스템의 가장 약한 고리 → 생성·배포·저장·사용·교체·폐기 생명주기 관리, HSM으로 물리 보호, 클라우드 [[KMS]], 용도별 키 분리, BYOK/HYOK
- **암호 민첩성 (Crypto-Agility)**: CBOM(Crypto Bill of Materials)으로 암호 자산을 목록화하고, 서비스 중단 없이 알고리즘을 교체할 수 있는 구조 설계
- **PQC 전환**: 기존 ECC + ML-KEM 하이브리드 → PQC 단독으로 단계적 전환 ([[양자내성암호|포스트 양자 암호]])
- **경량 암호**: IoT·엣지 환경에 NIST 경량 암호 표준(Ascon) 확산
