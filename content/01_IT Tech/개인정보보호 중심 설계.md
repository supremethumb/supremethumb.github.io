# 개인정보보호 중심 설계 (Privacy by Design)

---

## I. 나중이 아닌 처음부터, 개인정보보호 중심 설계의 개요

### 가. 정의

- 시스템·서비스·업무 절차의 **기획·설계 단계부터 운영·파기까지 개인정보보호를 기본 요소로 내재화**하는 설계 원칙 (Ann Cavoukian 제안, 7대 원칙)

### 나. 등장 배경 및 특징

| 구분 | 내용 |
| --- | --- |
| 사후 대응 한계 | 유출 후 조치로는 피해 회복 불가 |
| 규제 명문화 | GDPR 제25조 "Data Protection by Design and by Default" |
| 사전 예방 | 설계 단계에서 위험 식별·제거 |
| 기본값 보호 | 사용자가 아무것도 하지 않아도 최대 보호 |
| 사용자 중심 | 동의·철회·열람 등 정보주체 통제권 보장 |

### 나. 7대 원칙

| 구분 | 요소 | 설명 |
| --- | --- | --- |
| 사전 예방 | 사후 대응이 아닌 예방 | [[위협 모델링]]·[[개인정보 영향평가]]로 설계 단계 위험 제거 |
| 기본 설정 | Privacy as the Default | 최소 수집, 옵트인, 기본 비공개 설정 |
| 설계 내재화 | Embedded into Design | 부가 기능이 아닌 아키텍처 핵심 요소로 반영 |
| 포지티브섬 | Full Functionality | 기능과 프라이버시를 함께 달성 (제로섬 지양) |
| 전 생명주기 보호 | End-to-End Security | 수집부터 안전한 파기까지 [[암호화]]·접근 통제 |
| 가시성·투명성 | Visibility and Transparency | 처리 방침 공개, 감사 추적 |
| 사용자 존중 | Respect for User Privacy | 쉬운 동의·철회, 다크패턴 금지, 권리 행사 UI |

## III. 비교 및 동향

### 가. Security by Design vs Privacy by Design

| 비교 항목 | Security by Design | Privacy by Design |
| --- | --- | --- |
| 보호 대상 | 시스템·정보 자산 | 개인정보와 정보주체 권리 |
| 목표 | [[기밀성]]·[[무결성]]·[[가용성]] | 최소 수집, 통제권, 투명성 |
| 기법 | [[시큐어코딩]], 위협 모델링(STRIDE), 인증 | 가명·익명처리, PET, 동의 관리, LINDDUN |
| 관련 규제·제도 | 정보통신망법, ISMS | GDPR, [[개인정보보호법]], [[PbD 인증제도]] |

### 나. 동향

- **국제 표준**: ISO/IEC 31700(2023) 소비자 제품·서비스의 Privacy by Design 요구사항
- **AI 적용**: [[초거대 언어 모델|LLM]] 학습 데이터 정제, [[차분 프라이버시]]·[[연합 학습]] 등 PET를 설계 단계에서 적용
- **국내 인증**: 개인정보보호위원회의 PbD 인증 시범 운영으로 제품·서비스 단위 평가
