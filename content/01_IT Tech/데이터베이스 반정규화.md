# 데이터베이스 반정규화(De-Normalization)

---

## I. 무결성과 성능의 절충, 반정규화의 개요

### 가. 정의

- 정규화된 모델에서 **조회 성능 향상을 위해 테이블 병합·분할, 중복 컬럼, 중복 관계를 의도적으로 허용하는 물리적 설계 기법**

### 나. 특징

| 구분 | 내용 |
| --- | --- |
| 목적 | 다중 [[조인]]으로 인한 I/O·CPU 부하 감소 |
| 적용 시점 | 정규화 완료 후 물리 모델링 단계에서 선택적 적용 |
| 트레이드오프 | 조회 성능 ↑, 갱신 비용·정합성 위험 ↑ |
| 비정규화와 구분 | 정규화를 거친 뒤 의도적으로 되돌림 (처음부터 정규화하지 않은 것과 다름) |

---

## II. 적용 절차 및 기법

### 가. 반정규화 절차

```mermaid
flowchart LR
    A["1. 대상 조사<br/>(조회 빈도·범위·조인 수)"] --> B["2. 대안 검토<br/>(뷰·인덱스·파티션·캐시)"]
    B -->|"대안으로 부족"| C["3. 반정규화 적용<br/>(테이블·컬럼·관계)"]
    C --> D["4. 정합성 확보<br/>(트리거·배치·애플리케이션)"]
```

- 반정규화 전 뷰·인덱스·클러스터링 같은 대안을 먼저 검토하고, 적용 후에는 중복 데이터 동기화 수단을 함께 설계

### 나. 반정규화 기법

| 구분 | 요소 | 설명 |
| --- | --- | --- |
| 테이블 | 병합 | 1:1, 1:M 관계 테이블 통합, 슈퍼·서브타입 통합 |
| | 분할 | 수직 분할(컬럼 단위), 수평 분할(행 단위, [[파티셔닝]]) |
| | 추가 | 집계·이력·부분 테이블 추가 |
| 컬럼 | 중복 컬럼 | 조인을 피하려고 다른 테이블 컬럼을 복제 |
| | 파생 컬럼 | 합계·평균 등 계산값을 미리 저장 |
| | 이력·PK 컬럼 | 최근값 여부, 기본키 분리 컬럼 추가 |
| 관계 | 중복 관계 | 조인 경로 단축용 외래키 추가 |
| 정합성 | 동기화 | [[DML]] 시 트리거·배치·애플리케이션 로직으로 중복 데이터 일치 |

---

## III. 비교 및 동향

### 가. 정규화 vs 반정규화

| 비교 항목 | 정규화 | 반정규화 |
| --- | --- | --- |
| 목적 | 중복 최소화, 무결성 확보 | 조회 성능 향상 |
| 단계 | 논리 모델링 | 물리 모델링 |
| 장점 | [[Anomaly(이상현상)\|이상현상]] 방지 | 조인 감소 |
| 단점 | 조인 증가로 조회 성능 저하 | 갱신 부하, 정합성 위험 |
| 적합 환경 | [[OLTP]] | [[OLAP]]·DW·조회 위주 시스템 |

### 나. 동향

- **CQRS**: 쓰기 모델은 정규화, 읽기 모델은 반정규화·[[NoSQL (CAP 이론 BASE 속성)|NoSQL]]로 분리
- **구체화 뷰(Materialized View)**: 원본은 정규형 유지, 조인·집계 결과만 물리 저장
- **NoSQL 모델링**: 조회 패턴 중심 설계로 내장(Embedding)·중복을 기본 전략으로 사용 ([[NoSQL 데이터모델링 패턴]])
