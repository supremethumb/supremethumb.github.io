# 쿠버네티스(Kubernetes, K8s)

---

## I. 클라우드 네이티브 컨테이너 오케스트레이션 표준, 쿠버네티스의 개요

* **정의**: 대규모 분산 환경에서 컨테이너화된 애플리케이션의 배포, 스케일링, 로드 밸런싱, 무중단 운영을 자동화하는 선언적(Declarative) 기반 오픈소스 오케스트레이션 플랫폼
* **필요성 및 등장배경**:
* **마이크로서비스([[MSA (Micro Service Architecture)|MSA]]) 복잡도 급증**: 대규모 수백~수천 개 컨테이너의 수동 관리 한계 및 생명주기 관리 자동화 요구
* **[[HA(High Availability)|고가용성]] 및 복원력 확보**: 인프라 장애 발생 시 자동 복구(Self-healing) 및 [[무중단 배포]](Rolling Update, Canary) 필수화


* **특징**: 선언적 API(Desired State 유지), 표준 플러그인 인터페이스(CRI/CNI/CSI), 인프라 [[추상화]] 및 벤더 종속성(Lock-in) 배제

---

## II. 쿠버네티스의 아키텍처 및 핵심 구성요소

### 가. 쿠버네티스의 아키텍처 및 동작 원리

```mermaid
flowchart TB
    User["관리자 / CI/CD<br/>(kubectl)"]

    subgraph ControlPlane["Control Plane (Master Node)"]
        direction TB
        API["kube-apiserver<br/>(중앙 제어/REST API)"]
        ETCD[("etcd<br/>(분산 분산 저장소)")]
        Sched["kube-scheduler<br/>(노드 스케줄링)"]
        CM["kube-controller-manager<br/>(상태 제어 루프)"]
        CCM["cloud-controller-manager<br/>(CSP 인프라 연동)"]

        API <--> ETCD
        API <--> Sched
        API <--> CM
        API <--> CCM
    end

    subgraph WorkerNode["Worker Node"]
        direction TB
        Kubelet["kubelet<br/>(노드 에이전트)"]
        Proxy["kube-proxy<br/>(네트워크/iptables/IPVS)"]
        CRI["Container Runtime<br/>(containerd / CRI-O)"]

        subgraph PodGroup["Pod (실행 단위)"]
            App1["Container 1"]
            App2["Container 2"]
        end

        Kubelet --> CRI
        CRI --> PodGroup
        Proxy -.-> PodGroup
    end

    User == "요청" ==> API
    API <-- "상태 동기화" --- Kubelet


```

* **동작 원리**: 사용자가 `kubectl`을 통해 원하는 상태(Desired State)를 선언하면, `kube-apiserver`와 `etcd`를 거쳐 컨트롤러와 스케줄러가 작업 부하를 결정하고, 워커 노드의 `kubelet`이 런타임을 구동하여 실제 상태(Current State)를 지속적으로 일치시킴

### 나. 쿠버네티스의 핵심 기술/구성 요소

| 구분 | 요소기술(키워드) | 세부 설명 |
| --- | --- | --- |
| **제어 계층** | kube-apiserver | 쿠버네티스 클러스터의 모든 컴포넌트 간 통신 허브 및 REST API 엔드포인트 제공 |
| **상태 저장** | etcd | 클러스터의 모든 메타데이터와 Desired/Current 상태를 저장하는 일관성(CP) 기반 분산 키-값 저장소 |
| **배치 제어** | kube-scheduler | 파드의 리소스 요구량, 하드웨어 제약, 어피니티(Affinity) 등을 분석하여 최적의 워커 노드에 할당 |
| **상태 제어** | Controller Manager | 노드, 레플리카, 엔드포인트 등 리소스의 현재 상태를 감시하고 Desired State로 수렴시키는 제어 루프 |
| **노드 에이전트** | kubelet | 각 워커 노드에서 파드 스펙(PodSpec)을 전달받아 컨테이너의 정상 동작 및 헬스체크를 수행하는 데몬 |
| **네트워크 프록시** | kube-proxy | 노드 내 [[TCP]]/UDP 트래픽 라우팅을 관리하며 iptables, IPVS, eBPF를 통한 서비스 가상 IP 처리 |
| **런타임 인터페이스** | CRI (Container Runtime) | Kubernetes와 OCI 호환 런타임(containerd, CRI-O) 간 표준 통신 규격 (Dockershim 대체) |
| **확장 인터페이스** | CNI / CSI | 플러그인 기반 네트워크(Calico, Cilium) 및 외부 스토리지 볼륨 연동을 위한 표준 인터페이스 |

## III. 가상머신(VM) 오케스트레이션과의 비교 및 최신 동향

### 가. 쿠버네티스(K8s) vs 가상머신 오케스트레이터(OpenStack) 비교

| 비교 항목 | 쿠버네티스 (Kubernetes) | 오픈스택 (OpenStack) |
| --- | --- | --- |
| **관리 단위** | [[컨테이너]] 및 파드 (Pod) | 가상 머신 (VM, Instance) |
| **[[가상화]] 수준** | OS [[커널]] 공유 기반 [[프로세스]] 격리 (Cgroups, Namespaces) | 하이퍼바이저([[Hypervisor (VMM)|Hypervisor]], KVM) 기반 하드웨어 가상화 |
| **배포/기동 속도** | 초(Seconds) 단위 이하 고속 기동 | 분(Minutes) 단위 OS 부팅 소요 |
| **리소스 오버헤드** | 최소화 (게스트 OS 미탑재로 고집적도 실현) | 큼 (각 VM마다 독립 OS 커널 및 메모리 점유) |
| **네트워크 모델** | Pod-to-Pod 플랫 네트워크 (CNI 기반) | 오버레이/소프트웨어 정의 네트워크 (Neutron 기반) |
| **주요 활용 분야** | MSA, [[클라우드 네이티브]] 애플리케이션, AI 워크로드 | IaaS 인프라 가상화, 레거시 모놀리식 VM 운영 환경 |

* **향후 전망 및 기술 동향**:
* **eBPF 기반 네트워크 혁신**: 대규모 트래픽 처리를 위해 `iptables` 부하를 극복하고 커널 수준에서 패킷을 처리하는 **Cilium/eBPF** 도입 가속
* **AI/ML 인프라 표준화**: 대규모 언어 모델([[초거대 언어 모델|LLM]]) 분산 학습 및 서빙을 위한 **DRA(Dynamic Resource Allocation)**, [[GPU]] 슬라이싱(vGPU, MIG), **Kueue** 기반 일괄 작업(Batch) 큐잉 오케스트레이션 플랫폼으로 영역 확장 중
