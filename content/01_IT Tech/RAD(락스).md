# RAD (Rapid Application Development)

---

## I. 타임박스 안의 고속 개발, RAD의 개요

### 가. 정의

- **짧은 타임박스 안에서 사용자 참여(JAD)·프로토타이핑·CASE 도구·재사용 컴포넌트를 활용해 응용 시스템을 신속히 개발**하는 [[SDLC]] 모델 (James Martin, 1991)

### 나. 특징

| 구분 | 내용 |
| --- | --- |
| 등장 배경 | [[워터폴\|폭포수]]의 긴 개발 주기로는 비즈니스 변화 대응 곤란 |
| 타임박스 | 기능을 조정하더라도 정해진 기간(예: 60~90일) 내 완성 |
| 사용자 참여 | 현업 사용자가 설계·구축 전 과정에 상시 참여 |
| 적용 조건 | 모듈화 가능한 업무 시스템, 숙련 인력·도구 확보 필요 |

---

## II. 수행 단계 및 구성요소

### 가. RAD 4단계

```mermaid
flowchart LR
    P1["1. 요구 계획<br/>(Requirements Planning)"] --> P2["2. 사용자 설계<br/>(User Design)"]
    P2 --> P3["3. 구축<br/>(Construction)"]
    P3 -. "프로토타입 피드백" .-> P2
    P3 --> P4["4. 전환<br/>(Cutover)"]
```

- 업무 범위를 정한 뒤 사용자와 설계·구축을 반복해 요구를 확정하고, 시험·교육·데이터 전환을 거쳐 운영에 투입

### 나. 구성요소

| 구분 | 요소 | 설명 |
| --- | --- | --- |
| 일정 | 타임박싱 | 기간 고정, 범위를 조정해 일정 준수 |
| 협업 | JAD (Joint Application Design) | 개발자와 현업 사용자의 집중 워크숍으로 요구·설계 합의 |
| 개발 기법 | [[프로토타이핑 모델\|프로토타이핑]] | 동작하는 시제품으로 요구 확정 |
| 자동화 | CASE 도구 | 화면 설계, 코드·DB [[스키마]] 자동 생성 |
| 재사용 | 컴포넌트 [[재사용]] | 기성 모듈·라이브러리로 코딩 공수 절감 |
| 조직 | 소규모 숙련 팀 | 개발·현업이 함께하는 SWAT 팀 |

## III. 비교 및 동향

### 가. 폭포수 vs RAD vs 애자일

| 비교 항목 | [[워터폴\|폭포수]] | RAD | [[Agile\|애자일]] |
| --- | --- | --- | --- |
| 주기 | 수개월~수년 | 60~90일 타임박스 | 1~4주 스프린트 반복 |
| 사용자 참여 | 요구 정의·인수 시점 | JAD 중심 상시 참여 | 스프린트 리뷰마다 피드백 |
| 핵심 수단 | 문서·단계 통제 | CASE 도구·프로토타입 | 팀 협업·지속 통합 |
| 한계 | 변경 반영 곤란 | 대규모·고성능 시스템에 부적합, 숙련 인력 의존 | 대규모 아키텍처 사전 설계 부족 우려 |

### 나. 동향

- RAD에서 파생된 DSDM이 애자일 방법론의 하나로 발전
- OutSystems, Microsoft Power Platform 등 로우코드·노코드 플랫폼이 RAD 개념을 계승
- LLM 코드 생성으로 요구사항에서 UI·백엔드 시제품을 바로 만드는 형태로 확장
