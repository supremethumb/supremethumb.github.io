# 소프트웨어 테스트 프로세스 (Software Test Process)

---

## I. 체계적 결함 예방과 품질 보증을 위한 표준 생명주기 절차, 테스트 프로세스의 개요

* **정의**: 소프트웨어 개발 생명주기([[SDLC]]) 전반에 걸쳐 요구사항의 결함을 조기에 발견하고 품질을 보증하기 위해 계획부터 평가·보고에 이르기까지 일련의 체계적인 검증 활동을 수행하는 공학적 절차
* 품질 리스크 조기 식별(Shift-Left), 객관적 릴리즈 의사결정 지원 및 테스팅 표준(IEEE 29119 / ISTQB) 준수 목적
* 특징: 단계별 피드백 루프 구조, 테스트 계획부터 완료까지의 정형화된 페이즈, CI/CD 파이프라인 연계형 지속적 테스팅(Continuous Testing)

---

## II. 테스트 프로세스의 개념도 및 핵심 기술 요소

### 가. 테스트 프로세스(ISTQB / IEEE 29119 기준)의 아키텍처 및 동작 원리

```mermaid
flowchart LR
    subgraph TestProcess["Software Test Lifecycle Process"]
        direction LR
        P1["1. 테스트 계획 및 통제<br/>(Planning & Control)"] --> P2["2. 테스트 분석<br/>(Test Analysis)"]
        P2 --> P3["3. 테스트 설계<br/>(Test Design)"]
        P3 --> P4["4. 테스트 구현<br/>(Test Implementation)"]
        P4 --> P5["5. 테스트 실행<br/>(Test Execution)"]
        P5 --> P6["6. 테스트 평가 및 보고<br/>(Evaluation & Reporting)"]
    end

    REQ["요구사항 / 아키텍처 명세"] --> P1
    P6 --> OUT["품질 게이트 통과 및 릴리즈 승인"]

```

* 요구사항 분석을 기반으로 테스트 계획을 수립하고, 테스트 조건 분석·설계 및 구현을 거쳐 실제 케이스를 실행한 뒤, 결과 평가 및 종료 기준(Exit Criteria)을 만족할 때 릴리즈를 승인하는 구조

### 나. 테스트 프로세스의 핵심 구성 요소

| 분류 | 요소기술(키워드) | 세부 설명 |
| --- | --- | --- |
| 계획 단계 | 테스트 계획 및 통제 | 테스트 범위, 일정, 자원 배분, 리스크 관리 및 모니터링 체계 수립 |
| 분석 단계 | 테스트 분석 (Test Analysis) | [[요구사항 명세서]] 및 아키텍처를 기반으로 테스트할 대상 조건 식별 |
| 설계 단계 | 테스트 설계 (Test Design) | 경계값 분석(BVA), 동등 분할(EP) 등 기법을 활용한 테스트 케이스 구체화 |
| 구현 단계 | 테스트 구현 (Test Implementation) | 테스트 스위트 구성, 테스트 데이터 준비 및 자동화 스크립트 작성 |
| 실행 단계 | 테스트 실행 (Test Execution) | 테스트 케이스를 환경에 배포하고 실제 결과와 예상 결과 비교 수행 |
| 평가 단계 | 테스트 평가 및 보고 | 종료 기준(Exit Criteria) 달성 여부 판정 및 결함 리포트 발행 |
| 국제 표준 | IEEE 29119 / ISTQB | 소프트웨어 테스팅 전 과정의 표준 [[프로세스]] 및 용어 정의 규격 |
| 최신 트렌드 | AI 기반 테스트 자동화 | [[초거대 언어 모델|LLM]]을 활용한 테스트 케이스 자동 생성 및 UI 변경에 따른 자가 치유(Self-Healing) |

---

## III. 전통적 순차적 테스트 프로세스 vs 최신 애자일·CI/CD 연계 테스트 프로세스 비교

| 비교 항목 | 전통적 순차적 테스트 프로세스 (V-Model) | 최신 애자일 / CI/CD 연계 테스트 프로세스 |
| --- | --- | --- |
| **수행 시점** | 개발 완료 후 특정 마일스톤 시점에 일괄 수행 | 코드 푸시 및 빌드 시점마다 상시 자동 수행 (Continuous Testing) |
| **프로세스 유연성** | 요구사항 변경 시 테스트 계획 및 설계 전면 수정 소요 | 반복적 스프린트 주기에 맞춰 테스트 케이스 실시간 갱신 |
| **자동화 성숙도** | 수동 테스팅 비중이 높고 결함 발견 시점 지연 (Shift-Down) | 단위·통합·E2E 테스트 자동화 및 AI 에이전트 연계 (Shift-Left) |

* 최근 [[클라우드 네이티브]] 및 데브옵스 환경의 확장에 따라, 고정된 문서 중심의 사후 테스트 프로세스에서 벗어나 CI/CD 파이프라인 상에 테스트 단계를 실시간 임베디드하고 생성형 AI를 결합한 지능형 테스트 자동화 프로세스로 빠르게 전환되고 있음
