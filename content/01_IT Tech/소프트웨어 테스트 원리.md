# 소프트웨어 테스트 원리 (Software Testing Principles)

---

## I. 테스트의 한계와 전략을 담은 7원리, 테스트 원리의 개요

### 가. 정의

- 테스트를 효과적·효율적으로 수행하기 위해 **ISTQB가 정리한 테스트의 본질적 한계와 전략에 관한 7가지 일반 원리**

### 나. 필요성

| 구분 | 내용 |
| --- | --- |
| 한계 인식 | 완벽한 테스트가 불가능함을 전제로 자원 배분 |
| 전략 근거 | [[위험 기반 테스트]]·조기 테스트의 근거 제공 |
| 편향 방지 | "결함이 없다"는 과신과 확증 편향 경계 |
| 범용성 | 폭포수부터 애자일까지 개발 방식과 무관하게 적용 |

---

## II. 7원리 구조 및 내용

### 가. 7원리의 구조

```mermaid
flowchart LR
    subgraph L ["한계 인식"]
        P1["1. 결함 존재 증명"]
        P2["2. 완벽한 테스트 불가능"]
    end
    subgraph E ["효율 전략"]
        P3["3. 조기 테스트"]
        P4["4. 결함 집중"]
        P5["5. 살충제 패러독스"]
    end
    subgraph C ["정황 · 가치"]
        P6["6. 정황 의존"]
        P7["7. 오류 부재의 궤변"]
    end
    L --> E --> C
```

- 테스트의 한계를 인정하고, 효율적인 전략을 세우며, 사업 정황과 사용자 가치로 최종 판단

### 나. 7원리

| 구분 | 요소 | 설명 |
| --- | --- | --- |
| 한계 | 1. 결함 존재 증명 | 테스트는 결함이 있음을 보여 줄 뿐, 없음을 증명하지 못함 |
| | 2. 완벽한 테스트 불가능 | 모든 입력·경로 조합 테스트는 불가능, 위험·우선순위로 범위 결정 |
| 전략 | 3. 조기 테스트 | 요구·설계 단계부터 시작해 수정 비용 절감 (Shift-Left) |
| | 4. 결함 집중 | 소수 모듈에 다수 결함이 몰림 (파레토 80:20) |
| | 5. 살충제 패러독스 | 같은 케이스 반복으로는 새 결함을 못 찾음, 케이스 지속 갱신 (ISTQB v4: "Tests wear out") |
| 정황 · 가치 | 6. 정황 의존 | 안전 필수 시스템과 웹 서비스는 테스트 방식이 달라야 함 |
| | 7. 오류 부재의 궤변 | 결함이 없어도 사용자 요구를 못 맞추면 실패한 SW |

---

## III. 비교 및 동향

### 가. 전통적 적용 vs 최신 적용

| 원리 | 전통적 적용 | 최신 적용 (애자일 · [[DevOps]] · AI) |
| --- | --- | --- |
| 조기 테스트 | 명세 완료 후 테스트 계획 | [[TDD]], CI 정적 분석으로 즉시 피드백 |
| 살충제 패러독스 | 주기적 수동 케이스 리뷰 | LLM 케이스 생성, [[뮤테이션 테스트]]로 검출력 점검 |
| 결함 집중 | 경험 기반 취약 모듈 선정 | 커밋 이력·복잡도 기반 결함 예측 모델 |
| 오류 부재의 궤변 | 인수 테스트 시점 확인 | 사용자 피드백·[[탐색적 테스트]]로 상시 확인 |

### 나. 동향

- 완벽한 테스트 불가능·결함 집중 원리를 결합한 위험 기반 자원 배분이 표준 전략으로 정착
- 검증(명세 충족)뿐 아니라 확인(사용자 가치)을 강화해 오류 부재의 궤변 방지
