# 모니터 동기화 (Monitor)

---

## I. 언어가 보장하는 상호배제, 모니터의 개요

### 가. 정의

- 공유 데이터와 그 데이터를 다루는 프로시저를 하나로 묶고, **한 번에 하나의 프로세스·스레드만 모니터 안에서 실행되도록 보장**하는 고수준 동기화 구조 (Brinch Hansen·Hoare, 1970년대 제안)

### 나. 특징

| 구분 | 내용 |
| --- | --- |
| 자동 상호배제 | 진입 시 잠금·해제를 컴파일러·런타임이 처리, 프로그래머가 P/V 순서를 잘못 쓸 위험 제거 |
| 정보 은닉 | 공유 변수는 모니터 프로시저를 통해서만 접근 |
| 조건 동기화 | 조건 변수(Condition Variable)의 wait·signal로 특정 조건까지 대기 |
| [[세마포어]] 대비 | 세마포어보다 추상화 수준이 높고 오류가 적음, 표현력은 동등 |

---

## II. 구조 및 구성요소

### 가. 모니터 구조

```mermaid
flowchart LR
    EQ["진입 큐<br/>(Entry Queue)"] -->|"한 번에 하나만 진입"| M
    subgraph M["모니터"]
        direction TB
        SD["공유 데이터"]
        OP["프로시저 1..N"]
        INIT["초기화 코드"]
    end
    M -->|"wait"| CQ["조건 변수 큐<br/>x, y"]
    CQ -->|"signal"| M
```

- 모니터 안에서 조건이 안 맞으면 wait로 조건 큐에서 대기하며 잠금을 놓고, 다른 스레드의 signal로 깨어남

### 나. 구성요소

| 구분 | 요소 | 설명 |
| --- | --- | --- |
| 데이터 | 공유 변수 | 모니터 내부에서만 접근 가능한 지역 데이터 |
| 연산 | 프로시저 | 공유 변수를 다루는 유일한 경로 |
| | 초기화 코드 | 공유 변수 초기값 설정 |
| 대기열 | 진입 큐 | 모니터 진입을 기다리는 스레드 대기열 |
| | 조건 변수 큐 | 조건 변수별 대기열 |
| 연산 | wait(x) | 호출 스레드를 x의 큐에 넣고 모니터 잠금 해제 |
| | signal(x) | x의 큐에서 대기 중인 스레드 하나를 깨움, 대기자가 없으면 효과 없음 (세마포어 V와 차이) |

---

## III. 비교 및 동향

### 가. signal 의미론 비교

| 비교 항목 | Hoare 방식 (Signal-and-Wait) | Mesa 방식 (Signal-and-Continue) |
| --- | --- | --- |
| signal 후 실행 | 깨어난 스레드가 즉시 실행, 신호 보낸 스레드는 대기 | 신호 보낸 스레드가 계속 실행, 깨어난 스레드는 나중에 진입 |
| 조건 확인 | 깨어나면 조건 성립이 보장 → `if`로 충분 | 그사이 조건이 바뀔 수 있음 → `while`로 재확인 |
| 구현 | 문맥 교환이 추가돼 복잡 | 단순, 대부분의 실제 구현이 채택 |
| 사례 | 교과서 모델 | Java, POSIX pthread_cond, C# |

### 나. 세마포어 vs 모니터

| 비교 항목 | [[세마포어]] | 모니터 |
| --- | --- | --- |
| 수준 | 저수준 정수 변수 + P/V 연산 | 고수준 언어 구조 |
| 상호배제 | 프로그래머가 직접 P/V 배치 | 자동 보장 |
| 오류 가능성 | P/V 누락·순서 오류로 [[교착상태]] 위험 | 상대적으로 낮음 |

### 다. 동향

- **언어 내장**: Java `synchronized` + `wait/notify`, C# `lock` + `Monitor` 클래스가 Mesa 방식 모니터 제공
- **명시적 락·조건 변수**: Java `ReentrantLock`·`Condition`, C++ `std::mutex`·`std::condition_variable`로 조건 큐를 여러 개 두는 세밀한 제어
- **가상 스레드 대응**: Java 24(JEP 491)에서 `synchronized` 블록 안의 가상 스레드가 캐리어 스레드를 고정(Pinning)하던 문제 해소
