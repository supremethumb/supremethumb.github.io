# 소프트웨어 개발 방법론

---

## I. 개발 절차의 표준화, 소프트웨어 개발 방법론의 개요

### 가. 정의

- [[SDLC]] 전 과정의 **작업 절차·기법·산출물·도구를 체계적으로 정리하고 표준화한 공학적 개발 체계**

### 나. 필요성

| 구분 | 내용 |
| --- | --- |
| 등장 배경 | 주먹구구식(Build & Fix) 개발로 인한 소프트웨어 위기 극복 |
| 가시성 · 예측성 | 단계별 산출물로 진척 파악, 일정·비용 예측 가능 |
| 품질 · 생산성 | 검증된 기법과 표준 산출물로 품질 확보, 유지보수성 향상 |
| 진화 | [[프로세스]] 중심 → 데이터 중심 → 객체·컴포넌트 중심 → 협업·속도 중심으로 변화 |

---

## II. 방법론의 변천 및 유형

### 가. 변천 과정

```mermaid
flowchart LR
    ST["구조적<br/>(프로세스 중심)"] --> IE["정보공학<br/>(데이터 중심)"]
    IE --> OO["객체지향<br/>(객체 중심)"]
    OO --> CBD["CBD<br/>(컴포넌트 조립)"]
    CBD --> AG["애자일<br/>(반복 · 협업)"]
    AG --> DO["DevOps · 플랫폼 엔지니어링<br/>(개발 · 운영 통합)"]
```

- 기능 분해 중심에서 재사용·조립 중심을 거쳐, 변화 대응 속도와 개발·운영 통합을 중시하는 방향으로 진화

### 나. 유형별 특징

| 구분 | 방법론 | 설명 |
| --- | --- | --- |
| 전통적 | 구조적 | 하향식 기능 분해, DFD·자료사전·소단위 명세 활용 ([[데이터 흐름도]]) |
| | 정보공학 | 전사 관점 데이터 중심 설계, [[ISP (Information Strategy Plan)\|ISP]]·ERD 활용 |
| | [[객체지향]] | 데이터와 행위를 객체로 캡슐화, [[UML]] 기반 분석·설계 |
| | CBD | 독립 컴포넌트를 식별·조립해 [[재사용]]과 생산성 향상 |
| 경량 · 현대 | [[Agile\|애자일]] | 작동하는 SW와 변화 대응 중시, 짧은 반복 개발 ([[SCRUM\|Scrum]], XP, Kanban) |
| | [[DevOps]] · [[DevSecOps]] | 개발·보안·운영 협업과 CI/CD 자동화로 지속 배포 |
| | 플랫폼 엔지니어링 | 내부 개발자 플랫폼(IDP)으로 개발자 인지 부하 감소, 셀프서비스 환경 제공 |

## III. 비교 및 동향

### 가. 폭포수 vs 애자일 vs DevOps

| 비교 항목 | [[워터폴\|폭포수]] | 애자일 | DevOps |
| --- | --- | --- | --- |
| 핵심 가치 | 사전 계획, 문서화 | 변화 대응, 고객 가치 조기 전달 | 개발·운영 협업, 배포 자동화 |
| 주기 | 순차, 단일 릴리즈 (수개월~수년) | 스프린트 반복 (1~4주) | 상시 배포 (일 단위 이하) |
| 주요 산출물 | 요구사항 정의서, 설계서 | 동작하는 증분 | 파이프라인, 운영 지표 |
| 리스크 | 후반부 테스트 집중 | 반복마다 분산 | 작은 변경 단위로 최소화 |

### 나. 동향

- GitHub Copilot 등 AI 코딩 어시스턴트 확산으로 코딩보다 설계·검증 비중이 커지는 AI 보조 개발
- [[클라우드 네이티브]]·[[MSA (Micro Service Architecture)|MSA]] 환경의 복잡도를 줄이기 위한 플랫폼 엔지니어링 도입
- AI 모델을 포함한 시스템은 [[MLOps]]·[[LLMOps]]로 개발·운영 절차를 확장
