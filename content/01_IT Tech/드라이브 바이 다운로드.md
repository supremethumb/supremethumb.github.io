# 드라이브 바이 다운로드 (Drive By Download)

---

## I. 사용자 개입 없는 자동 감염 기법, 드라이브 바이 다운로드의 개요

드라이브 바이 다운로드(Drive By Download)는 사용자가 해커에 의해 침해된 악성·위조 웹페이지를 방문하는 것만으로, 별도의 클릭이나 다운로드 행위 없이 브라우저 및 플러그인의 취약점을 악용해 백그라운드에서 악성코드가 자동 설치·실행되는 사이버 공격 기법이다.

| 구분 | 내용 |
| :--- | :--- |
| **정의** | 웹페이지 방문만으로 사용자 인지/클릭 없이 취약점을 악용해 악성코드가 자동 감염되는 공격 기법 |
| **등장 배경** | 사회공학적 속임수(클릭 유도)의 한계를 극복하고 무결함(Zero-Click) 기반의 대량 자동 감염 구현 |
| **공격 메커니즘** | 웹서버 스크립트 변조 $\rightarrow$ 다단계 리다이렉션 $\rightarrow$ 환경 프로파일링 $\rightarrow$ 취약점 타격 및 페이로드 실행 |

---

## II. 드라이브 바이 다운로드의 개념도 및 핵심 기술 요소

### 가. 드라이브 바이 다운로드의 개념도 및 동작 원리

```mermaid
sequenceDiagram
    participant User as 사용자 (브라우저)
    participant Web as 침해된 정상 웹서버
    participant Exploit as Exploit 서버 (해커)

    Note over Web: 해커에 의해 악성 스크립트(iframe) 사전 주입됨
    
    User->>Web: 1. 일반적인 웹 페이지 접속 요청 (HTTP GET)
    Web-->>User: 2. 정상 콘텐츠 + 난독화된 악성 스크립트 응답
    
    Note over User: 브라우저가 스크립트 렌더링 중 자동 실행
    
    User->>Exploit: 3. 보이지 않는 iframe을 통한 악성 서버 리다이렉션
    Exploit-->>User: 4. 사용자 환경(OS, 브라우저 버전, 플러그인) 프로파일링
    
    Note over Exploit: 취약점 분석 및 적합한 Exploit 매칭
    
    Exploit->>User: 5. 맞춤형 익스플로잇 코드 및 페이로드 전달
    Note over User: 6. 취약점 악용으로 악성코드 다운로드 및 백그라운드 실행

```

* 취약점이 존재하는 엔드포인트(브라우저)가 침해된 웹 서버 방문 시, 숨겨진 리다이렉션 코드를 통해 Exploit 서버로 연결되어 악성코드가 자동 감염되는 [[프로세스]]

### 나. 드라이브 바이 다운로드의 핵심 기술 요소

| 구분 | 요소기술(키워드) | 세부 설명 |
| --- | --- | --- |
| **공격 도구** | 익스플로잇 킷 (Exploit Kit) | 사용자의 브라우저 및 플러그인 취약점을 자동으로 스캔하고 공격 코드를 배포하는 해킹 도구 (예: RIG, Fallout, Angler) |
| **공격 기법** | [[난독화]] (Obfuscation) | 보안 솔루션(WAF, 백신)의 시그니처 탐지를 우회하기 위해 JavaScript 및 iframe 코드를 알아볼 수 없게 변형 |
| **인프라** | 랜딩 페이지 (Landing Page) | 리다이렉션 된 사용자의 환경을 프로파일링하고, 실제 익스플로잇 코드를 인젝션하는 해커 측 웹 페이지 |
| **인프라** | 다중 리다이렉션 (TDS) | Traffic Direction System을 이용해 분석가 추적을 피하고 여러 경유지를 거쳐 최종 착취지로 트래픽 우회 |
| **페이로드** | 악성코드 (Payload) | 익스플로잇 성공 후 시스템에 설치되는 실질적인 악성 파일 ([[랜섬웨어]], 크립토재킹, 봇넷 에이전트 등) |
| **대응 기술** | RBI (원격 브라우저 격리) | 웹 콘텐츠 렌더링을 로컬 디바이스가 아닌 원격 가상 환경에서 수행하여 스크립트 실행을 물리적/논리적으로 격리 |
| **대응 기술** | [[EDR(Endpoint Detection and Response)\|EDR]] (엔드포인트 탐지/대응) | 백신이 탐지하지 못한 파일리스(Fileless) 공격이나 비정상적인 백그라운드 프로세스 실행 행위를 실시간 탐지 및 차단 |
| **대응 기술** | 패치 관리 시스템 (PMS) | OS, 웹 브라우저, 플러그인(PDF 리더 등)의 최신 보안 패치를 강제 적용하여 근본적인 공격 표면(취약점) 제거 |

## III. 유사 공격 기법과의 비교 및 향후 전망

### 가. 드라이브 바이 다운로드와 워터링 홀(Watering Hole) 비교

| 비교 항목 | 드라이브 바이 다운로드 (Drive By Download) | 워터링 홀 (Watering Hole) |
| --- | --- | --- |
| **핵심 목적** | 봇넷 구성, 랜섬웨어 유포 등 불특정 다수 감염 | 특정 타겟(기업, 기관)의 내부망 침투 및 정보 탈취 |
| **공격 대상** | 취약점이 있는 **불특정 다수** 방문자 | APT 공격 대상 집단이 **자주 방문하는 특정 웹사이트** |
| **작동 방식** | 방문 즉시 자동 다운로드 및 감염 유도 | 목표 대상이 접근할 때까지 잠복 및 선별적 익스플로잇 |
| **위협 수준** | 대규모 피해 발생 (개인 사용자 중심) | 치명적 정보 유출 및 시스템 파괴 (기업/국가 중심) |
| **기술적 성격** | 공격의 자동화 및 대량 유포(Exploit Kit 의존도 높음) | 표적형(Spear) 지능적 지속 위협(APT)의 초기 침투 수단 |

### 나. 향후 전망 및 대응 동향
- **파일리스(Fileless) 공격과의 결합 심화**: 디스크에 악성 실행파일을 생성하지 않고 브라우저 프로세스 메모리 상에서 직접 악성 쉘코드를 인젝션하는 파일리스 기법 확산.
- **원격 브라우저 격리(RBI) 및 샌드박싱 필수화**: 엔드포인트 디바이스에 웹 코드가 직접 실행되지 않도록 클라우드 기반 가상 컨테이너에서 렌더링 결과만 비디오 스트림으로 수신하는 격리 체계 확산.
- **[[제로 트러스트 보안모델|제로 트러스트]] 기반 패치 및 엔드포인트 지속 검증**: 비인가된 브라우저 확장의 실행 차단, 실시간 취약점 패치(PMS 자동화), 그리고 [[EDR(Endpoint Detection and Response)|EDR]]/XDR 기반의 백그라운드 이상 행위 실시간 차단 필수.
