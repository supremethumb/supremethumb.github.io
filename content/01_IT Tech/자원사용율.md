# 자원사용율 (Resource Utilization)

---

## I. 자원이 일한 시간의 비율, 자원사용율의 개요

### 가. 정의

- 측정 구간 동안 [[CPU]]·메모리·디스크·네트워크 등 **자원이 실제로 작업을 처리한 시간(또는 양)의 비율**, CPU 스케줄링에서는 최대화 대상인 CPU 이용률

### 나. 특징

| 구분 | 내용 |
| --- | --- |
| 스케줄링 기준 | CPU 이용률·[[처리량]]은 최대화, 반환·대기·응답시간은 최소화 |
| 병목 식별 | 이용률이 높은 자원이 시스템 성능의 병목 |
| 포화와 지연 | 이용률이 100%에 가까워질수록 대기열이 길어져 응답시간 급증 (대기행렬 이론) |
| 용량 계획 | 오토스케일링 임계치, 적정 규모(Right-sizing) 판단 근거 |

---

## II. 측정 구조 및 지표

### 가. 측정·제어 흐름

```mermaid
flowchart LR
    SYS["대상 시스템<br/>CPU, 메모리, 디스크, 네트워크"] -->|"지표 노출"| EXP["수집기<br/>node_exporter, cAdvisor"]
    EXP --> TSDB[("시계열 DB<br/>Prometheus")]
    TSDB --> AL["임계치 판정"]
    AL -->|"예: CPU 80% 초과"| AS["오토스케일링"]
    AS -.-> SYS
```

- OS가 집계한 자원 사용 지표(`/proc/stat` 등)를 수집해 추세를 보고 임계치 초과 시 자원 증설

### 나. 측정 지표

| 구분 | 요소 | 설명 |
| --- | --- | --- |
| CPU | %usr·%sys | 사용자·커널 모드 실행 시간 비율 |
| | %iowait | 처리할 작업 없이 미완료 I/O를 기다린 유휴 시간 비율 |
| | 부하 평균 (Load Average) | 실행 중·실행 대기(Linux는 D 상태 포함) 태스크 수의 이동 평균 |
| 메모리 | 사용량·스왑 | 사용 중 메모리, 스왑 입출력 빈도 (잦으면 [[스레싱\|스레싱]] 의심) |
| 디스크 | IOPS·처리량 | 초당 입출력 횟수, MB/s |
| | %util | 장치가 바쁜 시간 비율, 병렬 처리하는 SSD·NVMe에서는 100%라도 포화가 아닐 수 있음 |
| 네트워크 | 대역폭 사용률·Drop | 링크 대비 전송량, 큐 넘침으로 인한 패킷 손실 |
| 압박 지표 | Linux PSI | 자원 부족으로 태스크가 지연된 시간 비율 |

## III. 비교 및 동향

### 가. 프로비저닝 상태 비교

| 비교 항목 | 과소 할당 | 적정 할당 | 과다 할당 |
| --- | --- | --- | --- |
| 이용률 (예) | 지속적 90% 이상 | 평균 50~70% | 평균 20% 미만 |
| 영향 | 응답 지연, [[SLA]] 위반 위험 | 피크를 흡수할 여유 확보 | 비용 낭비 |
| 대응 | 스케일 업·아웃, 튜닝 | 추세 모니터링 | 인스턴스 축소, 유휴 자원 회수 |

### 나. 동향

- **예측형 오토스케일링**: 과거 사용률 패턴을 학습해 급증 전에 미리 자원 확보 (AWS Predictive Scaling 등)
- **FinOps**: 사용률 데이터를 비용과 연결해 유휴·과다 자원을 찾아 적정 규모로 조정
- **USE 방법론**: 자원마다 이용률(Utilization)·포화(Saturation)·오류(Errors)를 함께 보는 성능 분석 접근
