## II. 가상화의 핵심 구현 기술 및 분류
가상화는 추상화하는 대상 자원과 하이퍼바이저의 구동 방식에 따라 다양하게 분류되며, 전체 IT 인프라(SDDC)를 구성하는 근간이 됩니다.
### 1. 하이퍼바이저(Hypervisor) 아키텍처에 따른 분류

| 구분 | Type 1 (베어메탈 / 네이티브) | Type 2 (호스트형) |
| --- | --- | --- |
| 개념 | 하드웨어 위에 하이퍼바이저가 직접 설치되어 가상 머신(VM)을 제어하는 구조 | 기존 운영체제(Host OS) 위에 소프트웨어 애플리케이션 형태로 하이퍼바이저가 설치되는 구조 |
| 특징 | OS 오버헤드가 없어 성능과 안정성이 우수, 엔터프라이즈 서버 환경에 적합 | 설치가 간편하고 기존 PC 환경에서 타 OS 테스트 시 용이하나 성능 손실이 발생 |
| 솔루션 | VMware ESXi, Microsoft Hyper-V, KVM, Xen | VMware Workstation, Oracle VirtualBox |

### 2. 가상화 대상 자원에 따른 분류

| 대상 분야 | 주요 기술 명칭 | 핵심 기능 및 특징 |
| --- | --- | --- |
| 서버 (Compute) | 서버 가상화 | 물리적 서버를 분할하여 다수의 가상 머신(VM) [[프로비저닝]] (최근 MicroVM으로 경량화) |
| 네트워크 | [[SDN(Software Defined Network)|SDN]] / [[NFV]] | 네트워크 제어부와 데이터 전송부를 분리하고, [[스위치 (Layer 3 Switch)|스위치]]/방화벽을 소프트웨어로 가상화 |
| 스토리지 | SDS (Storage) | 다양한 물리적 저장장치를 논리적인 단일 스토리지 풀로 묶어 할당 및 관리 (예: vSAN) |
| 데스크톱 | VDI (데스크톱) | 중앙 서버에 가상 데스크톱 환경을 구축하고 씬 클라이언트 등을 통해 원격 접속 및 제어 |
| 하드웨어 | [[GPU]] 가상화 (vGPU) | 단일 물리 GPU를 분할하여 여러 VM/컨테이너에 할당 (NVIDIA MIG 등 AI 인프라 핵심) |

## III. 2026년 최신 가상화 기술 동향 및 발전 방향
### 1. KubeVirt 중심의 가상화와 컨테이너의 융합 (Cloud-Native Virtualization)
과거 시장을 주도하던 특정 상용 가상화 솔루션의 라이선스 정책 변경(Broadcom의 VMware 인수 여파 등)으로 인해, 엔터프라이즈 환경에서 기존 VM 워크로드를 [[쿠버네티스]](Kubernetes) 환경으로 이관하는 움직임이 가속화되었습니다. 2026년 현재, 컨테이너 오케스트레이션 플랫폼 내에서 레거시 VM을 파드(Pod)처럼 관리할 수 있게 해주는 KubeVirt 기술이 차세대 표준 가상화 인프라로 강력하게 부상하고 있습니다.
### 2. AI 워크로드를 위한 vGPU 및 가속기 가상화 고도화
대규모 언어 모델([[초거대 언어 모델|LLM]])과 생성형 AI의 폭발적 수요로 인해 GPU 자원의 효율적 배분이 기업 IT의 핵심 과제가 되었습니다. 이에 따라 단일 고성능 GPU를 하드웨어 수준에서 여러 인스턴스로 분할하는 MIG(Multi-Instance GPU) 기술과 vGPU(가상 GPU) 할당 기술이 가상화 솔루션과 긴밀히 결합하여, AI 인프라의 TCO(총소유비용)를 획기적으로 절감하고 있습니다.
### 3. 서버리스 아키텍처를 지원하는 마이크로VM (MicroVM) 및 WebAssembly 부상
기존 VM의 무거운 부팅 시간과 컨테이너의 보안 격리 한계를 동시에 극복하기 위해, 수 밀리초(ms) 만에 구동되면서도 하드웨어 수준의 강력한 보안 격리를 제공하는 경량 가상화(Firecracker, Kata Containers 등) 기술이 서버리스 컴퓨팅(FaaS)의 기반 기술로 확고히 자리 잡았습니다. 더불어 엣지([[EDGE|Edge]]) 환경에서는 가상 머신 대신 Wasm(WebAssembly)이 초경량 가상화 런타임으로 도입되고 있습니다.

끝.

# 가상화 (Virtualization)

---

## I. 물리적 자원의 논리적 추상화, 가상화의 개요

### 가. 가상화(Virtualization)의 정의

- 물리적인 컴퓨터 리소스(CPU, 메모리, 스토리지 등)를 추상화하여, 물리적 자원을 논리적으로 통합(Aggregation)하거나 분할(Partitioning)하여 자원 효율성을 극대화하는 기술.
- 대부분의 서버는 용량의 10~15%만 사용되므로, 가상화를 통해 효용률(Utilization Rate)을 70% 이상으로 높이고 TCO(Total Cost of Ownership)를 절감하는 것이 주 목적임.

### 나. 가상화의 핵심 특징 (키워드)

- 공유(Sharing): 물리적 자원을 다수 사용자에게 분할 제공.
- 단일화(Aggregation): 여러 물리 자원을 하나의 논리적 자원으로 통합.
- 에뮬레이션(Emulation): 물리적 객체와 동일한 기능을 논리적으로 수행.
- 절연(Insulation): 자원 교체나 장애 시에도 서비스 연속성 보장.

---

## II. 가상화의 기술 분류 및 핵심 기술요소

### 가. 가상화 기술 분류 (차별화 도식화 - Tree 구조)

- 도식화 포인트: 단순히 나열하지 않고 대상(Target)별로 계층화하여 서버, 스토리지, 네트워크, 데스크톱으로 분류하고, 각각의 세부 기술을 매핑하여 가시성을 높임.

### 나. 가상화 핵심 기술요소

| 구분 | 기술요소 | 설명 |
| --- | --- | --- |
| 서버 | [[Hypervisor (VMM)|Hypervisor]] | - 물리적 하드웨어와 OS 사이의 추상화 계층 (VMM)<br>- Type 1 (Bare-metal), Type 2 (Hosted) 로 구분 |
|  | Partitioning | - 하나의 물리 시스템을 여러 개의 독립된 실행 환경으로 분할 |
|  | Live Migration | - 서비스 중단 없이 가상 머신(VM)을 다른 물리 서버로 이동 |
| OS | Container | - cgroups(자원할당), namespaces(격리)를 이용한 경량 가상화<br>- [[도커|Docker]], Kubernetes 등이 대표적 |
| 스토리지 | LUN | - Logical Unit Number, 물리적 디스크를 논리적 단위로 관리 |
|  | SDS | - Software Defined Storage, HW 독립적인 스토리지 관리 |

---

## III. 가상머신(Virtual Machine)과 컨테이너(Container) 비교

| 비교 항목 | 가상머신 (Virtual Machine) | [[컨테이너|컨테이너 (Container)]] |
| --- | --- | --- |
| 가상화 레벨 | 하드웨어 레벨 가상화 (Hypervisor) | OS 레벨 가상화 (Engine) |
| Guest OS | 존재함 (무거움, 부팅 느림) | 없음 (Host OS 공유, 가벼움) |
| 격리성 | 하드웨어 수준의 완벽한 격리 (보안성 높음) | [[프로세스]] 수준 격리 (보안성 상대적 낮음) |
| 성능 | 오버헤드 큼 (Guest OS 구동 비용) | 오버헤드 적음 (Native 성능에 근접) |
| 주요 기술 | VMware, Xen, KVM | Docker, LXC, Kubernetes |

- 최근 동향: [[클라우드 네이티브]](Cloud Native) 환경 확산에 따라 무거운 VM 방식에서 경량화된 컨테이너 및 쿠버네티스(Orchestration) 중심으로 전환되고 있음.
