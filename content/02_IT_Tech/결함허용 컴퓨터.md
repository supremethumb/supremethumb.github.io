# 결함허용 컴퓨터(FTS)


## I. 무중단 서비스를 위한 신뢰성 기술, 결함 허용 시스템(FTS)의 개요

### 가. 결함 허용 시스템(Fault Tolerant System)의 정의

- 시스템 내 일부 부품이나 소프트웨어에 결함(Fault)이 발생하더라도, 예비 부품 가동이나 오류 은폐 기술을 통해 시스템 전체의 중단 없이 정상적인 기능을 수행하는 시스템임.
### 나. FTS의 핵심 메커니즘 및 필요성

- **핵심 메커니즘:** 중복성(Redundancy) 확보, 결함 감지(Detection), 결함 격리(Isolation), 결함 회복(Recovery).
- **필요성:** 금융권 계정계, 항공우주 제어 시스템, 자율주행차 등 인명 및 재산 보호가 직결되는 Mission Critical 분야의 필수 요건임.

- **동작 원리:** 동일한 작업을 수행하는 여러 모듈을 병렬 배치하고, 보터(Voter)가 결과를 비교하여 다수결로 최종 출력을 결정함(Fault Masking). 결함 발생 모듈은 시스템 중단 없이 교체 가능함.
### 나. FTS의 핵심 기술 및 구성 요소

| **분류** | **핵심 기술** | **기술 설명 및 특징** |
| --- | --- | --- |
| **하드웨어 중복** | **TMR (Triple Modular)** | 3개의 모듈과 보터를 사용하여 결함을 즉시 은폐 (Masking) |
|  | **Pair-and-Spare** | 두 쌍의 하드웨어가 서로 감시하며 결함 시 예비 쌍으로 전환 |
| **소프트웨어 중복** | **Recovery Blocks** | 이전 상태 저장(Checkpoint) 후 결함 시 대체 블록 실행 (RB) |
|  | **N-Version Programming** | 동일 요구사항을 서로 다른 설계자로 구현하여 논리 오류 방지 |
| **데이터 중복** | **[[RAID]] (Mirroring/Parity)** | 디스크 결함 시 데이터 유실을 방지하기 위한 복제 및 패리티 |
|  | **Checkpointing** | 시스템 상태를 주기적으로 저장하여 결함 시 복구 지점 제공 |
| **시간 중복** | **Instruction Retry** | 오류 발생 시 동일 명령어를 재실행하여 일시적 결함 해소 |
| **복구 전략** | **Fail-Soft (Graceful)** | 결함 시 중요도가 낮은 기능을 정지하고 핵심 기능만 유지 |

## III. FTS와 고가용성(HA)의 비교 및 최신 동향

### 가. FTS vs HA (High Availability) 비교

| **항목** | **결함 허용 시스템 (FTS)** | **고가용성 시스템 (HA)** |
| --- | --- | --- |
| **목표** | 무중단 서비스 (Zero Downtime) | 신속한 복구 ([[HA(High Availability)|High Availability]]) |
| **결함 처리** | 결함 즉시 은폐 (Fault Masking) | 결함 감지 후 절체 (Failover) |
| **비용/복잡도** | 매우 높음 (전용 하드웨어 필요) | 상대적으로 낮음 (소프트웨어 위주) |
| **적용 분야** | 국방, 의료, 금융 핵심 인프라 | 일반 엔터프라이즈 서버, 웹 서비스 |

### 나. 최신 기술 동향

- **Chaos Engineering:** 시스템의 견고성을 확인하기 위해 클라우드 환경에 의도적으로 결함을 주입하여 FTS 성능을 검증하는 방식 확산 (Netflix Chaos Monkey).
- **Self-Healing:** Kubernetes 등 [[클라우드 네이티브]] 환경에서 [[컨테이너]] 결함 발생 시 자동으로 재시작하고 트래픽을 격리하는 자동 복구 기술 고도화.
