작업 분석은 일반 사용자가 작업을 수행하고 의도한 목표를 달성하는 방법을 자세히 이해하기 위해 실제 사용자를 관찰하여 학습하는 과정입니다., 작업 분석은 웹 사이트와 응용 프로그램이 지원해야 하는 작업을 식별하는 데 도움이 되며 적절한 콘텐츠 범위를 결정하여 사이트 탐색 또는 검색을 구체화하거나 재정의하는데도 도움이 된다.
## 태스크 분석의 목적
인터페이스 디자인을 위한 사용자 및 작업분석에서 JoAnn Hackos 와 Janice Redish 는 작업 분석을 수행하면 다음을 이해하는 데 도움이 된다고 말합니다.
- 사용자의 목표는 무엇입니까? = 그들이 달성하려고 하는 것
- 사용자가 이러한 목표를 달성하기 위해 실제로 수행하는 작업
- 사용자가 작업에 가여오는 경험(개인적, 사회적, 문화적)
- 사용자가 물리적 환경에 미치는 영향
- 사용자의 이전 지식과 경험이 미치는 영향:
	- 그들이 일에 대해 어떻게 생각하는지
	- 작업을 수행하기 위해 따르는 워크플로
## 태스크 분석을 수행해야 하는 경우
특히 설계 작업 이전에 프로세스 초기에 작업 분석을 수행하는 것이 중요합니다. 작업 분석은 다음을 포함하여 사용자 중심 설계 프로세스의 여러 다른 측면을 지원하는 데 도움이 됩니다.
- 웹사이트 요구사항 수집
- 콘텐츠 전략 및 사이크 구조 개발
- 와이어 프레임 및 프로토 타이핑
- 사용성 테스트 수행
## 태스크 분석 유형
작업 분석에는 여러 유형이 있지만 가장 일반적으로 사용되는 기술은 다음과 같습니다.
- 인지 작업 분석은 의사 결정, 문제 해결, 기억, 주의 및 판단이 필요한 작업을 이해하는데 중점을 둡니다.
- 계층적 작업 분석은 높은 수준의 하위 작업을 분해하는 데 중점을 둡니다.
## 태스크 분석 수행법
작업 분석에는 적인 것에사ㅓ 매우 구체적인 것까지 여러 수준의 조회가 있을 수 있습니다. 시장 조사, 경쟁 분석, 웹 메트릭 분석 외에도 다양한 사용자 조사 기법을 통해 주요 과제를 식별할 수 있습니다. UXPA 의 Usability Body of Knowledge 는 고급 작업을 다음 단계로 분해하는 프로세스를 세분화합니다.
1. 분석할 작업을 식별합니다.
2. 이 높은 수준의 작업을 4 ~ 8 개의 하위 작업으로 나눕니다. 하위 작업은 목표 측면에서 지정되어야 하며 그 사이에 전체 관심 영역을 다루어야 합니다.
3. 완료되었는지 확인하는 각 하위 작업의 계층화된 작업 다이어그램을 그립니다.
4. 서면 계정과 분해 다이어그램을 생성합니다.
5. 분해에 관여하지 않았지만 일관성을 확인할 만큼 작업을 잘 알고 있는 다른 사람에게 분석을 제시합니다.
전반적으로 일관성을 유지할 수 있도록 하위 작업을 분해할 세부 수준을 결정해야 한다는 점에 유의하는 것이 중요합니다.
## 예
작업을 식별하기 위해 최소한 사용자에게 전체 작업이 무엇인지 또는 현재 작업을 어떻게 수행하는지 물어볼 수 있습니다. 사용자가 웹 사이트에서 수행하려는 전반적인 작업은 무엇입니까?
- 가까운 연로한 친척을 위해 요양원을 찾고 있습니다.
- 피부암 치료 옵션에 대한 정보를 얻으려고 합니다.
- 지불 기한이 되었을 때 이메일 알림을 받기 위해 등록하려고 합니다.
사용자는 현재 작업을 어떻게 완료하고 있습니까? 사람들은 다음을 사용하여 해당 작업을 완료하고 있습니다.
- 검색 엔진 사용
- 사이트 탐색
- 다른 사이트 사용
