자연스러운 환경에서 사용자를 관찰할 수 있어 사용자가 제품을 사용하는 방식을 더 잘 이해할 수 있습니다.
인터뷰어는 사용가자 실험실이 아닌 사용자 자신의 환경에서 작업하는 것을 보고 경청합니다. 상황별 인터뷰는 결과적으로 더 자연스럽고 때로는 더 현실적입니다. 또한 일반적으로 랩 테스트보다 덜 형식적이며 작업이나 스크립트를 사용하지 않습니다.
## 수행 방법
상황별 인터뷰에서는 사용자가 작업하는 것을 보고 듣습니다. 일반적으로 사용자에게 작업이나 시나리오를 제공하지 않습니다. 사용자가 무엇을 하고 있거나 생각하고 있는지 이해하기 위해 사용자가 사이트를 탐색할 때 질문할 수 있습니다. 결과는 일반적으로 정량적 측정 데이터가 아니라 정성적 관찰 데이터 입니다.
## 상황별 인터뷰에서 배우는 것
상황별 인터뷰는 관찰과 인터뷰를 결합합니다. 사용자에게 이동하면 사용자의 환경와 사용자가 작업하는 실제 기술을 볼 수 있습니다. 결과적으로 다음과 같은 질문에 답할 수 있습니다.
- 사용자가 직면한 모든 문제
- 그들이 사용하는 장비
- 그들의 공간이 어떻게 구성되어 있는지
- 마우스와 키보드 중 선호도
- 그들이 가지고 있는 인터넷 연결 유형
- 일반 적업 또는 대상 작업을 완료하는 데 얼마나 걸리는지
- 작업을 완료하는 데 도움이 필요한 경우 사용자를 도울 의향이 있고 사람이 있는지 여부
## 상황별 인터뷰와 사용성 테스트 결합
사용성 테스트에서는 일반적으로 모든 사용자가 동일한 시나리오를 완료하도록 하여 동인한 작업을 시도하는 여러 사람의 데이터를 비교하게 됩니다. 상황에 맞는 인터뷰에서 자신의 작업을 수행하는 자신의 환경에서 사람들의 행동을 관찰합니다. 그러나 다음을 통해 상황별 인터뷰와 사용성 테스트를 결합할 수 있습니다.
- 상황에 맞는 인터뷰 중 시나리오를 가져갑니다. 사용자가 자신의 환경에서 자신의 작업을 수행하는 것을 관찰하고 몇 가지 작업을 시도하도록 요청하는 것을 결합합니다.
- 사용성 테스트 중에 사용자를 인터뷰하여 사이트에 올 수 있는 질문, 문제, 작업의 종류를 찾습니다. 사용자가 자신의 작업을 수행하도록 하되 작업도 수행하도록 합니다.
웹사이트 사용성 테스트는 종종 비공식적이며 상황별 인터뷰와 매우 유사하게 수행됩니다. 그러나 사용성 테스트는 비공식적이고 정성적인 것부터 상당히 공식적이고 양적인 것까지 다양할 수 있습니다.
