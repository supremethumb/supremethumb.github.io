MVP(Minimum Viable Product, 최소 기능 제품)는 제품에 대한 가설을 가장 작은 형태로 만들어 시장에 내놓고, 실제 사용자의 반응을 통해 빠르게 검증하는 접근이다. 에릭 리스의 *린 스타트업*에서 제시되며, "완벽한 제품을 만들어 출시"하는 전통적 접근의 대안이다.

## MVP 의 본질

- **학습이 목적**: 매출이 아니라 "이 가설이 맞는가?"를 확인하는 도구다.
- **실패 비용 최소화**: 작게 만들어 빠르게 틀린 부분을 찾는다.
- **반복 개선**: Build → Measure → Learn 루프를 빠르게 돌린다.

## 잘못 이해되는 MVP

| 오해 | 실제 |
| --- | --- |
| 기능이 부실한 제품 | 가설을 검증하기 위한 *최소한의 완결된* 제품 |
| 베타 버전과 동일 | 베타는 출시 직전, MVP 는 가설 검증 단계 |
| 한 번 만들고 끝 | 가설마다 새 MVP 를 만든다 |

## MVP 의 형태

- **랜딩페이지 MVP**: 기능을 만들기 전에 신청 페이지로 수요를 측정
- **컨시어지 MVP**: 자동화 대신 사람이 수작업으로 서비스 제공
- **위저드 오브 오즈**: 사용자에겐 자동화처럼 보이지만 뒤에서는 사람이 처리
- **프로토타입 MVP**: 실제 코드는 최소화하고 UI 흐름만 보여줌

## 좋은 MVP 의 조건

1. 검증하려는 **가설이 명확**하다.
2. 가설이 틀렸을 때 빠르게 **방향을 바꿀(Pivot)** 수 있다.
3. 정량/정성 데이터를 모두 **수집할 수 있다**.
